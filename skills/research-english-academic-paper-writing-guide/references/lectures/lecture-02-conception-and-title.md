## 0. 本讲的核心定位

这一讲是整个系列从“为什么要写论文、论文是什么”进入“如何以 A 类论文的思路组织科研与写作”的第一步。老师没有先从英文句子或论文模板讲起，而是把论文写作的起点放在更前面：**一篇论文在真正决定要解决什么科学问题、用什么类型的方法去解决时，就已经在很大程度上决定了它更像 A 类论文，还是更像 C 类论文。**

本讲围绕两个关键词展开：**立意**与**标题**。

立意不是泛泛地“选一个方向”或“跟一个热点”，而是判断研究是否聚焦领域前沿、是否探究本质问题、是否提出具有普适性的解决方法。标题也不是最后随便概括一下论文内容，而是论文核心问题、技术创新、知识产权边界和传播能力的高度凝练。

## 1. 课堂开场：这一讲要回答什么问题？

老师开场说明：本系列讲座继续围绕“英文学术论文写作指南”展开，第二讲聚焦“学术研究之写作思路”。这一讲会从一篇 CCF-A 类学术论文出发，逐步分析它从标题、摘要、引言、相关工作、方法、实验，到最后总结和参考文献的每个环节，与 C 类论文之间到底有什么根本差别。

本讲虽然最终重点落在“标题”，但它的逻辑起点不是标题本身，而是论文的立意：

- 论文要解决的科学问题是否本质；
- 方法是否围绕本质问题设计；
- 实验是否证明了方法对问题的解决；
- 标题是否能够把问题与创新凝练出来。

老师强调，A 类论文与 C 类论文的区别，不只是英语是否流畅、图是否好看、实验结果是否高一点，而是在“做什么问题、为什么做、怎么做、怎么证明”这些最底层的科研逻辑上就已经拉开差距。

**页面主体结构：左右对比。**

左侧是绿色标题 **CCF-A**，右侧是红色标题 **CCF-C**，中间用竖线分隔。

#### CCF-A 侧

- 科学问题：聚焦领域前沿，探索本质问题
- 解决方法：专注核心挑战，具普适性方法

页面左下方嵌入一篇论文示例：

- 论文题目：**Mucko: Multi-Layer Cross-Modal Knowledge Reasoning for Fact-based Visual Question Answering**
- 会议：**IJCAI 2020**
- 页面中的论文截图展示了一个视觉问答场景：输入图像中有红色消防栓，左侧有 dense captions 和问题 “What is the red cylinder object in the image is used for?”，右侧是 Cross-Modal Knowledge Reasoning 的图结构，节点和边把视觉信息、语义信息、事实知识连接起来，最终答案为 “firefighting”。

#### CCF-C 侧

- 科学问题：追逐领域热点，解决表面问题
- 解决方法：盲从热门方法，模型增量修改

页面右下方嵌入一篇论文示例：

- 论文题目：**Feature integration analysis of bag-of-features model for image retrieval**
- 期刊/年份标注：**Neurocomputing 2011**
- 页面中的流程图大意：数据库图像经过 SIFT Feature、LBP Feature 等特征抽取，进行 SIFT-LBP Feature 的特征融合，再经 Weighted K-means、Codebook、Bag-of-Features Histogram 和 Similarity Matching，输出检索结果。

**课堂讲解复现：**

老师从“论文立意”讲起。她指出：一篇论文在真正决定做什么样的科学问题时，就在一定程度上决定了它更可能是 A 类论文还是 C 类论文。

A 类论文通常寻找的是能够聚焦科研前沿、探究领域本质的问题。它不是简单追一个热点，也不是看到某个任务流行就跟着做，而是要看这个任务背后到底有什么真正核心的问题。与之对应，A 类论文的解决方法会围绕本质问题展开，专注核心挑战，并且具有一定普适性，不只是对某个数据集或某个特定任务有效。

C 类论文往往追逐热点：什么方法热、什么任务热，就跟着做；别人研究什么，自己也研究什么。这样的问题常常停留在表层。方法上也常常是把已有热门方法拿过来，做一些增量、很微小的修改，然后在某些特定任务或特定数据集上提升一点指标。

老师用两篇自己的论文进行对比。右侧的 2011 年工作做的是跨模态检索，方法层面主要是把当时流行的 SIFT、LBP 等特征进行融合，做特征拼接和 bag-of-features 模型改进。虽然当时也有贡献，也做了大量实验，但从今天看，这类工作更偏表面、更偏增量。

左侧的 2020 年 IJCAI 工作 Mucko 做的是知识型视觉问答。这个任务要求机器看图回答问题，不仅要融合视觉信息与问题文本，还要关联外部知识，才能回答正确。它本质上仍然涉及不同类型特征之间如何互补融合，但方法不再只是把特征拼在一起，而是从人类认知和跨模态推理的角度出发，思考如何共同表征不同模态的信息，如何在模态之间自适应地寻找互补线索，并进行融合和推理。因此它挖掘的是更本质的问题，并提出更有针对性、也更有普适性的图神经网络推理方法。

**本页关键结论：**

A 类论文与 C 类论文的差距不是从写作润色才开始，而是从科研立意开始。选择什么问题、怎样定义问题、方法是否围绕核心问题设计，都会决定论文的层次。

### Slide 3：问题、方法、实验是否相互呼应

**页面标题：**

从科学问题是否探究本质说起

**页面主体结构：左右对比。**

#### CCF-A

- 问题-方法-实验，相互呼应
- 问题：有理有据，足够具体
- 方法：针对问题设计，每一步设计目标明确
- 实验：针对方法逐一证明，针对动机逐一分析

#### CCF-C

- 问题-方法-实验，各有其说
- 问题：大家都在研究，所以我研究
- 方法：step1 -> step2 -> step3
- 实验：达到了 SOTA，缺乏分析

**课堂讲解复现：**

老师进一步把 A 类论文和 C 类论文的差异从“立意”推进到“写作逻辑”。A 类论文的问题、方法、实验是相互呼应的：问题提出有理有据，而且足够具体；方法的每一步都是针对问题设计的，每一步都有明确目标；实验也是围绕方法逐一证明，并围绕动机逐一分析。

C 类论文则常常变成“问题、方法、实验各说各话”。问题部分的逻辑是：这个方向很热，大家都在研究，所以我也研究。方法部分像技术报告，按照 step1、step2、step3 机械描述流程，却没有解释为什么这样设计、每一步解决哪个问题、步骤之间如何协作。实验部分只强调达到了 SOTA，但缺少结果背后的原因分析，也没有证明性能提升是否真正来自方法改进、是否真正回应了前面提出的问题。

老师强调，审稿人很难从这种“各说各话”的论文中看到核心创新，因为创新不在某一个孤立步骤里，而在问题、方法、实验之间的逻辑闭环里。

**本页关键结论：**

论文不是技术流程说明书。A 类论文必须让审稿人看到：问题为什么重要，方法为什么这样设计，实验如何证明方法解决了问题。

### Slide 4：一篇论文的组成

**页面标题：**

一篇论文的组成

**页面文字内容：**

- 标题：核心问题与创新点的高度凝练
- 摘要：动机、亮点与效果的概要介绍
- 引言：动机、现状、方法和贡献介绍
- 相关工作：引言现有工作的详细介绍
- 研究方法：引言模型部分的详细介绍
- 实验分析：引言模型效果的详细介绍
- 总结展望：经过实验验证后给的结论
- 致谢：对作者以外人员/机构的感谢
- 参考文献：正文出现的按照格式引用

**页面视觉结构描述：**

页面使用不同颜色的菱形项目符号区分论文各组成部分：标题为红色，摘要为紫色，引言为绿色，相关工作为青色，研究方法为黄色，实验分析为橙色，总结展望为深蓝色，致谢为蓝紫色，参考文献为灰色。

**课堂讲解复现：**

老师解释，一篇完整论文包含多个环节，每一部分都有它需要证明或强调的主题。学生常常困惑于摘要、引言、相关工作、方法部分之间内容重叠：摘要和引言都要讲动机，引言和相关工作都要讲现有工作，引言和方法都要讲自己的模型。那么不同部分到底讲什么、讲到什么力度、如何避免重复车轱辘话，就是写作中必须明确的问题。

这一页相当于整套写作课后续内容的总纲。标题要高度凝练核心问题与创新点；摘要概述动机、亮点和效果；引言负责建立动机、现状、方法和贡献；相关工作展开引言中现有工作的细节；研究方法展开引言中模型部分的细节；实验分析展开引言中模型效果的细节；总结展望给出经过实验证明后的结论；致谢与参考文献则承担规范性功能。

本讲从这一总纲中的第一个部分开始：标题。

### Slide 5：一篇论文的组成——标题

**页面标题：**

一篇论文的组成——标题

**页面文字内容：**

基本要求（不超过 15 个单词）

- 英文形式规范
- 语言精炼简洁
- 范围大小适当

好标题

- 反映核心问题
- 突出技术创新
- 保护知识产权
- 易于记忆传播

**课堂讲解复现：**

老师指出，很多同学不太重视标题，觉得只要用几个词概括论文内容即可。但实际上标题非常难，也非常重要。标题是审稿人看到论文时的第一印象，会影响审稿人对论文创新性、问题核心性和研究边界的初始判断。

标题是对一篇论文到底解决什么问题、有什么创新性的高度凝练。如果作者不能在有限字数内把这些说清楚，往往说明作者自己对论文的核心问题和创新边界也没有想清楚。这样写出来的论文就可能无法围绕核心内容不断强化和证明，整体显得松散，看起来没有解决真正的问题。

老师把标题要求分成两层。

第一层是基本要求：英文形式要规范，不能有语法错误；标题不能太长，一般不超过 15 个单词；语言要精炼简洁；研究范围要适当，不能把一篇小论文写成像本科、硕士、博士论文那样试图解决巨大问题。

第二层是好标题的要求：

1. **反映核心问题。** 标题要体现到底做的是一个任务，还是不同任务之间共性的科学问题。
2. **突出技术创新。** 标题中不能只说“解决了特征融合”，而要用简洁清晰的语言指出用什么技术创新解决这个问题。
3. **保护知识产权。** 如果某个模型名或技术名是作者首先提出的，标题可以帮助建立这个工作的识别度和边界。
4. **易于记忆传播。** 一个朗朗上口、容易记忆的标题或模型名，更有利于学术影响力扩散；一个复杂、难读、难记的名字，会让别人很难在交流中准确提到你的工作。

### Slide 6：标题 Bad Cases

**页面标题：**

一篇论文的组成——标题 (Bad Cases)

**页面列出的反例与红字批注：**

1. **From shallow to deeper: compositional reasoning over graphs for visual question answering**  
   批注：太宽泛！

2. **PERT: adaPtive Evidence-driven Reasoning neTwork for Machine Reading Comprehension with Unanswerable Questions**  
   批注：不规范！

3. **Understanding like humans: multimodal representation for the visual information in visual dialog**  
   批注：没依据！

4. **Graph Neural Networks for Image-Text Matching**  
   批注：没创新！

5. **A Plug-and-Play novel Tree Loss Function for Unbiased Scene Graph Generation based on Upgraded Transformer framework**  
   批注：太冗余！

6. **KBGN: Knowledge-Bridge Graph Network for Adaptive Vision-Text Reasoning in Visual Dialogue.**  
   批注：难记忆！

**课堂讲解复现：**

老师逐一分析这些反例。

第一个标题 “From shallow to deeper” 看起来吸引眼球，但过于抽象和宽泛，更像学术报告或 tutorial 的题目，不适合作为一篇具体学术论文的标题。论文标题需要科学、客观、准确地说明具体怎样解决问题，而不是用玄乎、宽泛的表达夺人眼球。

第二个标题试图把模型名 PERT 的每个字母嵌到不同单词中的不同位置，于是出现 “adaPtive”“neTwork” 这种中间字母大写的写法。老师认为这种写法非常不规范。模型缩写可以来自若干关键词的首字母或连续字母，但不能跳跃地从单词中间抽字母，更不应在论文标题中用不规范大小写突出缩写来源。

第三个标题 “Understanding like humans” 使用了缺乏客观依据的说法。关于人类到底如何理解、如何思考，现有科学研究并没有统一共识。作者可以用已有论文支撑方法灵感，但不能把未经证实的主观判断写进标题，甚至作为论文立论依据。标题必须客观、科学、准确。

第四个标题 “Graph Neural Networks for Image-Text Matching” 结构上没有语法问题，也清楚地表达了方法和任务。但老师指出，如果这个题目出现在图神经网络刚兴起的 2016、2017 年，它可能足够有新意；但当图神经网络和图文匹配都已经发展多年，再用这么笼统的题目，就看不出核心创新。标题要更细致地刻画具体方法和具体问题，而不是只把一个成熟方法套到一个成熟任务上。

第五个标题把太多技术细节塞进题目：plug-and-play、novel tree loss、unbiased scene graph generation、upgraded transformer framework 等全部出现，导致真正核心创新被细节淹没。标题不需要面面俱到，而应只凝练最关键的一两个创新点。

第六个标题整体问题不大，但模型名 KBGN 没有实际含义，也不朗朗上口，不便于记忆和传播。老师提醒，模型命名不仅要“有一个名字”，还要好读、好记、利于扩散。

**本页标题反例清单：**

- 太宽泛：标题像报告题目，不像论文题目。
- 不规范：为了凑缩写破坏英文大小写规范。
- 没依据：使用主观、未证实、不可验证的表述。
- 没创新：标题只体现成熟方法加成熟任务，看不出增量贡献。
- 太冗余：堆砌太多方法细节，淹没核心创新。
- 难记忆：模型名无意义、不顺口、不利于传播。

### Slide 7：标题 My Own

**页面标题：**

一篇论文的组成——标题 (My Own)

**页面列出的示例：**

1. **MuKEA: Multimodal Knowledge Extraction and Accumulation for Knowledge-based Visual Question Answering (CVPR 2022)**
2. **ET-BERT: A Contextualized Datagram Representation with Pre-training Transformers for Encrypted Traffic Classification (WWW 2022)**
3. **CogTree: Cognition Tree Loss for Unbiased Scene Graph Generation (IJCAI 2021)**
4. **DualDV: An Adaptive Dual Encoding Model for Visual Dialogue (AAAI 2020)**
5. **Mucko: Multi-Layer Cross-Modal Knowledge Reasoning for Fact-based Visual Question Answering (IJCAI 2020)**
6. **DAM: Deliberation, Abandon and Memory Networks for Generating Detailed and Non-repetitive Responses in Visual Dialogue (IJCAI 2020)**

**课堂讲解复现：**

老师给出自己近几年发表在 CCF-A 类会议上的论文标题作为正例。她指出，这些标题都遵循了前面的原则：首先有一个明确、易传播的模型或方法名称；其次，标题后半部分包含了到底解决什么问题、用什么方法解决。

以 **MuKEA** 为例，问题是 knowledge-based visual question answering，即知识型视觉问答；方法创新是 multimodal knowledge extraction and accumulation，即多模态知识抽取与积累。标题同时交代了任务边界和技术创新。

以 **ET-BERT** 为例，任务是 encrypted traffic classification，即加密流量分类；技术创新是 contextualized datagram representation with pre-training transformers。老师特别解释，这类流量数据看不见内容、不知道语义，因此如何做预训练、如何表征看不见语义的东西，是它突破现有技术能力边界的关键。标题要把这种突破点体现出来。

其他如 CogTree、DualDV、Mucko、DAM 也都采用类似结构：模型名或方法名 + 技术核心 + 任务范围。这样的标题便于审稿人和读者快速理解论文贡献，也便于后续学术传播。

## 3. 本讲知识结构重建

### 3.1 论文层次的第一分水岭：立意

本讲最重要的底层判断是：**论文的层次首先由立意决定，而不是由写作技巧决定。**

A 类论文更倾向于：

- 关注领域前沿；
- 探索本质问题；
- 提出能回应核心挑战的方法；
- 方法具有一定普适性；
- 问题、方法、实验之间形成闭环。

C 类论文更容易表现为：

- 追逐热点；
- 解决表面问题；
- 盲从热门方法；
- 对模型做增量修改；
- 只在特定任务或数据上提升一点指标；
- 论文写作变成技术流程描述。

这意味着，在开始写论文之前，作者必须先问自己：

1. 我解决的是领域里的本质问题，还是只是一个表层现象？
2. 我的方法是为了这个问题专门设计的，还是把热门方法搬过来？
3. 我的实验是在证明“方法解决问题”，还是只是在展示指标高？
4. 我的标题是否能让审稿人立刻看到核心问题与核心创新？

---

### 3.2 A 类论文的闭环：问题 - 方法 - 实验

本讲反复强调：问题、方法、实验必须相互呼应。

#### 问题层面

A 类论文的问题要“有理有据，足够具体”。有理有据意味着问题不是凭空想象，也不是因为“大家都在研究”，而是来自领域现状、真实挑战和已有方法的不足。足够具体意味着作者清楚知道自己要解决的是哪个核心矛盾，而不是泛泛说“提升性能”“解决特征融合”。

#### 方法层面

A 类论文的方法要“针对问题设计，每一步设计目标明确”。每个模块、每个损失函数、每个推理过程都应能回答：它解决了前面提出问题中的哪一部分？为什么需要它？不用它会怎样？它与其他部分如何协同？

#### 实验层面

A 类论文的实验要“针对方法逐一证明，针对动机逐一分析”。实验不只是证明结果达到 SOTA，更要证明每个方法设计的必要性、合理性和有效性，还要分析为什么提升发生、提升是否来自所提出的关键机制。

---

### 3.3 标题的本质：不是标签，而是边界定义

标题不是论文写完后随手添加的标签，而是对论文边界的定义。

一个好的标题必须完成四件事：

1. **定义问题边界。** 读者看到标题就知道论文处理的是哪个任务、哪个科学问题或哪个共性挑战。
2. **定义技术贡献。** 读者看到标题就知道方法创新在哪里，而不是只看到一个泛泛的技术类别。
3. **定义知识产权。** 好的模型名或方法名能让别人记住“这个技术最早来自这篇论文”。
4. **定义传播入口。** 好标题能被读者、审稿人、报告人和后续论文作者方便地提起。

因此，标题不是越炫越好，也不是越全越好，而是要在有限词数内实现最准确的凝练。

---

## 4. 标题写作操作法

### 4.1 基本规范检查

写完标题后，先做基础检查：

- 是否存在语法错误？
- 是否符合英文标题大小写规范？
- 是否一般控制在 15 个单词以内？
- 是否避免了过长的从句、堆砌和口号？
- 是否避免把一个小论文的范围写得过大？
- 是否能让非本领域但相关方向的审稿人读懂基本意思？

### 4.2 核心问题检查

继续问：

- 标题是否说明了研究对象？
- 标题是否说明了核心任务或科学问题？
- 标题是否避免了“某热门方法 for 某热门任务”的空泛套用？
- 标题中的问题是否足够具体？
- 标题是否能让审稿人感觉这个问题值得研究？

### 4.3 技术创新检查

继续问：

- 标题是否体现了主要技术创新？
- 标题中的创新是否太泛，如只写 “feature fusion”“graph neural networks”“deep learning”？
- 标题是否把最关键的一两个贡献提炼出来，而不是堆满所有细节？
- 标题是否能体现该方法相对已有技术的能力边界突破？

### 4.4 命名与传播检查

继续问：

- 模型名是否好读？
- 模型名是否好记？
- 模型名是否有意义，或至少与论文核心思想相关？
- 缩写是否来自合理的连续字母或首字母？
- 是否避免为了凑缩写而使用奇怪的大写、跳跃取字母？
- 标题是否便于在报告、论文引用、学术交流中传播？

## 5. 标题反例诊断模板

当看到一个标题时，可以按照以下方式诊断。

### 5.1 太宽泛

表现：标题像口号、报告题、tutorial 题目，缺少具体科学问题和技术路径。

本讲反例：

> From shallow to deeper: compositional reasoning over graphs for visual question answering

诊断：前半句 “From shallow to deeper” 过于抽象，不能客观说明具体问题和方法。

改进方向：减少口号式表达，直接呈现核心技术机制和任务边界。

### 5.2 不规范

表现：为了凑模型名，把单词中间字母大写，或者使用跳跃、不连续的缩写来源。

本讲反例：

> PERT: adaPtive Evidence-driven Reasoning neTwork for Machine Reading Comprehension with Unanswerable Questions

诊断：标题中的大小写服务于缩写，而不是服务于英文规范。

改进方向：模型缩写应来自自然、连续、可解释的词组，标题正文保持正常英文书写。

### 5.3 没依据

表现：使用“像人类一样理解”等缺乏可验证依据的主观表述。

本讲反例：

> Understanding like humans: multimodal representation for the visual information in visual dialog

诊断：人类如何理解本身不是一个已被统一证实的客观事实，不能作为标题依据。

改进方向：用可验证、可客观支撑的科学术语描述方法或目标。

### 5.4 没创新

表现：标题只是成熟方法加成熟任务，看不出具体增量。

本讲反例：

> Graph Neural Networks for Image-Text Matching

诊断：当图神经网络和图文匹配都已发展多年，这个标题无法体现具体创新。

改进方向：加入更细粒度的机制、约束、推理方式、表示方式或能力突破。

### 5.5 太冗余

表现：把论文中许多细节都塞进标题，导致核心贡献不突出。

本讲反例：

> A Plug-and-Play novel Tree Loss Function for Unbiased Scene Graph Generation based on Upgraded Transformer framework

诊断：标题堆砌过多修饰和技术细节，不利于审稿人抓住关键贡献。

改进方向：只保留最核心的一两个创新点和任务边界。

### 5.6 难记忆

表现：模型名生硬、无意义、不顺口。

本讲反例：

> KBGN: Knowledge-Bridge Graph Network for Adaptive Vision-Text Reasoning in Visual Dialogue.

诊断：虽然结构基本合理，但 KBGN 难读、难记，不利于传播。

改进方向：模型名尽量短、顺口、有意义，能与核心思想产生联系。

## 6. 好标题的可复用模板

本讲没有给出机械模板，但从正例中可以抽象出几类结构。

### 6.1 模型名 + 技术核心 + 任务边界

形式：

> ModelName: Core Technical Mechanism for Target Task

示例：

> MuKEA: Multimodal Knowledge Extraction and Accumulation for Knowledge-based Visual Question Answering

适用场景：有明确模型名，且模型名需要在领域内被记住。

### 6.2 模型名 + 表征方式 + 学习框架 + 任务

形式：

> ModelName: A Representation with Learning Framework for Target Task

示例：

> ET-BERT: A Contextualized Datagram Representation with Pre-training Transformers for Encrypted Traffic Classification

适用场景：核心贡献在于新的表示方式、预训练方式或建模框架。

### 6.3 方法过程短语 + 思想 + 任务

形式：

> Verb1, Verb2, and Verb3: High-level Strategy for Target Task

示例：

> Sketch, Ground, and Refine: Top-Down Dense Video Captioning

适用场景：方法可以被高度概括为一组阶段性动作，且这些动作本身有记忆点。

### 6.4 能力突破 + 任务

形式：

> Capability Target Task

示例：

> Zero-Shot Text-to-Image Generation

适用场景：核心创新是某种能力边界的突破，如 zero-shot、few-shot、open-vocabulary、instruction-following 等。

## 7. 把本讲转化为论文写作前的自问清单

在正式写论文标题之前，先回答下面的问题。

### 7.1 立意层面

- 我做的是领域前沿问题，还是跟风热点？
- 我解决的是本质问题，还是表面问题？
- 这个问题是否有明确的研究依据？
- 这个问题是否足够具体？
- 这个问题是否值得一篇论文来解决？

### 7.2 方法层面

- 方法是否围绕核心挑战设计？
- 每一步设计目标是否明确？
- 方法是否具有一定普适性？
- 方法是否只是热门方法的增量修改？
- 方法中的每个模块是否都能对应一个问题动机？

### 7.3 实验层面

- 实验是否逐一证明方法设计？
- 实验是否逐一回应研究动机？
- 是否分析了结果提升背后的原因？
- 是否说明提升是否来自方法改进？
- 是否避免只写“达到 SOTA，提升若干百分点”？

### 7.4 标题层面

- 标题是否不超过约 15 个单词？
- 标题是否英文规范？
- 标题是否精炼？
- 标题范围是否适当？
- 标题是否反映核心问题？
- 标题是否突出技术创新？
- 标题是否帮助保护知识产权？
- 标题是否易于记忆和传播？

## 8. 本讲可复用的“论文标题审稿人第一印象”判断法

假设你是审稿人，只看标题，尝试回答四个问题：

1. 这篇论文到底研究什么问题？
2. 这个问题是否是核心问题？
3. 这篇论文的技术创新是什么？
4. 我是否能在十秒后复述这个工作的名字或核心思想？

如果只看标题无法回答前两个问题，说明标题没有反映核心问题。  
如果无法回答第三个问题，说明标题没有突出技术创新。  
如果无法回答第四个问题，说明标题不利于记忆传播。

## 10. 一句话总结

第二讲真正要建立的不是“标题怎么写”的小技巧，而是一种从立意到标题的科研写作观：**先找到本质问题，再围绕问题设计方法，再用实验证明方法，最后用标题把核心问题与技术创新压缩成一个规范、精炼、可传播的入口。**

于静老师说明本讲的核心目标：以一篇 CCF-A 类学术论文为例，从标题、摘要、引言、相关工作方法、实验，一直到最后总结和参考文献，逐一分析每个环节中 A 类论文和 C 类论文最大的区别是什么；并说明每一部分具体应该以什么逻辑去写、重点存在哪些问题，以及如何改进论文中对应存在的问题。

## 一、从立意说起：科学问题是否探究本质（PPT 第 2–3 页）

### 1.1 幻灯片内容（PPT 第 2 页，原文精准转录 + OCR 交叉核对）

标题：**科学问题根植领域前沿，探索本质问题 vs. 盲目跟随领域热点，解决表面问题**
副标题对比：**解决思路：紧扣核心挑战，兼备普适性方法 vs. 跟随热门方法，模型增量修改**

页面下方并列展示两篇论文（均为于静老师本人论文）作为对比案例：

**左侧（CCF-A 类，晚近工作）：**
> **Mucko: Multi-Layer Cross-Modal Knowledge Reasoning for Fact-based Visual Question Answering**
> 作者：Zihao Zhu, Jing Yu, Yujing Wang, Yajing Sun, Yue Hu, Qi Wu

**右侧（对比案例，C 类期刊，早期工作）：**
> **Feature integration analysis of bag-of-features model for image retrieval**
> 作者：Jing Yu, Zengchang Qin, Tao Wan, Xi Zhang
> 发表于 **Neurocomputing, 2011**
> 配图展示"Retrieval Sample"（检索样例）示意图。

**说明（关于 transcript 中年份表述的核实）：** transcript 口述中提到对比论文时，年份表达出现了"2021"等含糊表述（推测为逐字稿语音识别对数字的误听误转，原话应指多年前、于静老师读研究生阶段发表的工作）。经比对 PPT 原始页面，该对比论文明确标注为 **Neurocomputing 2011**，而非 transcript 中出现的其他年份表述，本文档以 PPT 原文时间为准。

### 课堂讲解

> 一篇论文它在真正决定要做什么样的科学问题的时候，其实就在一定程度上决定了它到底是能够发 A 类的论文还是 C 类的论文。

于静老师首先给出 A 类与 C 类论文在"问题选择"层面的根本区别：

- **A 类论文：** 找的是能够聚焦科研前沿、探究领域本质的问题；解决思路都围绕着如何核心地解决这一本质问题展开，且方法具有一定普适性，不局限于特定任务或特定数据集。
- **C 类论文：** 往往是追逐热点——现在什么方法热、什么任务热，就跟着做什么；在方法上则是追踪已有热门方法，在特定任务、特定数据上做非常微小的增量改进，指标只有很小的提升。

随后，于静老师用自己的两篇论文作对比说明这一区别：

**早期工作（右侧，Neurocomputing 2011，C 类）：** 解决的是跨模态检索任务，但本质问题是"不同模态特征的融合"。当时的思路是拿来比较流行的特征表示方式（如 SIFT 特征、LBP 特征），直接做特征拼接（融合）。她坦言："当然我们提了一个新的框架，是我们比较新的一个思路，但是在特征融合这个层面，其实只是说把现有当时比较新的一些特征抽取方法进行融合……从解决的思路来看，还是比较表面、相对来说比较增量的一些工作。"

**近期工作（左侧，IJCAI 2020，CCF-A，即 Mucko）：** 解决的是视觉问答（Visual Question Answering）任务——给机器一张图像和一个相关问题，希望机器能"看图回答问题"。她指出，这个任务本质上要求的核心能力，同样是"不同类型特征怎么样做互补融合"这一问题，与十年前那篇论文的本质问题是相通的。但这次的方法"更从人类认知的本质出发，怎么样合理地、以共同的方式去表征不同模态的信息，怎么样在不同模态信息之间像人推理问题一样，自适应地找到它们之间互补的线索进行融合和推理"——即提出了一种基于图神经网络（Graph Neural Network）的全新方法来挖掘更本质的问题。

> 所以我想举这两个例子，想对比说明 CCF-A 这个论文和 C 类论文，大家其实选择我到底要去解决什么样的问题、到底选择哪种类型的方法，就决定了在你写作之前，其实就决定了你到底这篇论文是不是能中一个 A 类的论文。

### 1.2 幻灯片内容（PPT 第 3 页：从科学问题是否探究本质说起）

标题：**从科学问题是否探究本质说起**

版面为 CCF-A / CCF-C 两栏对比（原文精准转录）：

| | CCF-A | CCF-C |
| --- | --- | --- |
| 总体特征 | 问题—方法—实验，相互呼应 | 问题—方法—实验，各自其说 |
| 问题 | 有理有据，凝聚共识 | 大家都在研究，所以我研究 |
| 方法 | 针对问题设计，每一步设计目标明确 | step1 -> step2 -> step3（技术报告式罗列） |
| 实验 | 针对方法逐一证明，针对动机逐一分析 | 只看结果，缺乏分析 |

### 课堂讲解

于静老师在此进一步从"写作"角度对比 A 类和 C 类论文的差异（承接上文"问题/方法"层面的差异，扩展到写作呈现层面）：

**问题层面：** A 类论文写的是非常具体、真实的问题；C 类论文的思路往往是"现在这个方向研究非常热，大家都在研究某一个问题，我也不去分析这到底是不是这个任务的核心问题，因为大家研究的多，所以我也研究这种问题"。

**方法层面：** A 类论文对每一个方法环节的描述，都具体针对"到底解决了整个问题的哪一个环节"给出解释说明，且每个环节之间的方法步骤环环相扣，整体形成解决问题的完整方案，非常有针对性。C 类论文（或更低 level 的会议论文）的写作思路则是"第一步怎么做、第二步怎么做、第三步怎么做"，完全是按照技术报告的思路写学术论文——这样的写法导致审稿人很难发现核心创新性在哪里，也看不出每一步为什么这样设计、不用其他方法，以及不同步骤之间如何协作解决整体问题。

**实验层面：** A 类论文的每一个实验都从不同维度、不同角度证明"我解决了这个问题"以及"我方法里每一个环节的正确性和合理性"。C 类论文往往只是拿数据说"我的实验结果达到了现在最好的水平"，缺乏对实验结果的解释——只描述"A 模型的实验结果是什么样的，B 模型比 A 模型又提升了几个百分点"，完全没有分析背后为什么提升、提升是否真的是因为方法改进解决了对应问题所带来的。

> 所以大的方面，不管是从问题、方法还是实验，A 和 C 类论文，我想说从这些角度都是存在很大很大的差别。

## 二、一篇论文的组成（PPT 第 4 页）

### 幻灯片内容（原文精准转录，OCR + 惯例学术论文结构交叉核对）

标题：**一篇论文的组成**

- 标题：核心问题与创新点的高度凝练
- 摘要：动机、亮点与效果的概要介绍
- 引言：动机、现状、方法和贡献介绍
- 相关工作：详尽现有工作的详细介绍
- 研究方法：引出模型部分的详细介绍
- 实验分析：呈现模型效果的详细介绍
- 总结展望：经过实验验证后给出的结论
- 致谢：感谢基金、老师和同学（该条目 OCR 识别噪声较大，依据学术论文标准结构及页面项目符号数量推断补全，供参考）
- 参考文献：正文出现的按照格式引用

### 课堂讲解

> 那么我们下面再来看一篇论文，其实包含了这么多完整的环节，那每一部分其实都有它一定要去证明或者强调的一些主题。

于静老师指出，很多同学常见的困惑是：不知道摘要、引言、相关工作里都有介绍现有工作的内容，研究方法和引言里也都有介绍自己方法的内容，那么不同部分到底应该侧重讲哪些内容？以及整篇文章不同环节到底要呈现给审稿人怎样的"加分内容"，而不是完全重复车轱辘话。她说明这一问题会在后续讲次中逐一展开，讲解每一部分的边界、重点突出的内容，以及写到什么程度才能更好地发挥该部分在全文中的作用。本讲首先聚焦标题。

## 三、一篇论文的组成——标题：基本要求与好标题的标准（PPT 第 5 页）

### 幻灯片内容（原文精准转录）

标题：**一篇论文的组成——标题**

**标题要求（不超过 15 个单词）：**
- 英文形式规范
- 语言精炼简洁
- 范围大小适当

**好标题：**
- 反应（映）核心问题
- 突显学术创新
- 保护知识产权
- （第四项：结合课堂讲解补全为"易于传播记忆"）

### 课堂讲解

> 标题其实大家可能不太重视它，觉得反正就是我随便写一个概括论文内容的几个字就可以了，但其实我想说，标题非常难。

于静老师首先纠正一个常见误区：标题绝非随意概括几个字即可，而是审稿人看论文时的**第一印象**，直接决定了审稿人对这篇论文创新性、是否解决核心问题的最初判断。好标题要对"论文到底解决什么问题、有什么样的创新性"给出一个非常明确的边界界定；如果不能在有限字数内把这些说清楚，恰恰说明作者自己对"这篇论文到底要解决什么问题、核心创新性到底是什么"并没有清晰认识——进而导致全文内容无法围绕核心不断强化、论证，显得散乱，看起来没有解决什么问题。

**标题基本要求：**
- 不能出现语法错误
- 字数不能太多，大概 15 个单词以内
- 语言要足够精简
- 范围不能太大——"就像你的硕士论文、本科论文、博士论文一样，你不可能一篇小的论文解决非常大的问题"

**好标题的四条标准（逐条讲解）：**

1. **反映核心问题：** 是要做一个什么样的任务，还是想解决不同任务之间共性的一个问题，需要能够清晰点出来并在标题中反映。
2. **技术创新要清晰：** 用清晰的话描述解决这个问题最大的技术贡献，而不是非常模糊。她举例："我就解决了特征融合的问题"这种表述太笼统——特征融合本身只是任务里面临的一个具体问题，需要明确用什么样的方法解决这个问题，并用简洁的词表达出来。
3. **保护知识产权（大家常忽视）：** 如果题目写得特别简单或抽象概括，很难让别人记住这是你的工作。可以通过给模型命名等方式，在题目里体现你的技术是你率先提出的，从而保护知识产权。
4. **易于传播记忆：** 论文名字、模型名字是否朗朗上口、易于记忆和传播，而不是起一个特别难记或复杂的题目，导致别人在提及你的工作时还需要大量语言描述才能说清楚——这不利于学术影响力的扩展。

## 四、标题反面案例逐条剖析（PPT 第 6 页）

### 幻灯片内容（原文精准转录，标题原文均来自 PDF 文本层直接提取，可信度高）

标题：**一篇论文的组成——标题 (Bad Cases)**

页面列出 6 个反面案例标题（均取自于静老师学生的论文初稿）：

1. *From shallow to deeper: compositional reasoning over graphs for visual question answering*
2. *PERT: adaPtive Evidence-driven Reasoning neTwork for Machine Reading Comprehension with Unanswerable Questions*
3. *Understanding like humans: multimodal representation for the visual information in visual dialog*
4. *Graph Neural Networks for Image-Text Matching*
5. *A Plug-and-Play novel Tree Loss Function for Unbiased Scene Graph Generation based on Upgraded Transformer framework*
6. *KBGN: Knowledge-Bridge Graph Network for Adaptive Vision-Text Reasoning in Visual Dialogue*

（每条标题旁均有简短红字批注，因 OCR 在此类小号红色批注文字上噪声较大，具体批注文字以下方课堂讲解的逐条复原为准。）

### 课堂讲解：逐条剖析六个反面案例

**案例① "From shallow to deeper: compositional reasoning over graphs for visual question answering"：** 标红部分"from shallow to deeper"（从浅层到更深度）想表达方法的演进，但这种"非常 fun、非常抽象"的题目，适合做学术报告或 tutorial 的标题，但不适合用作具体论文的题目——论文题目要用"科学客观的语言"，不要写得这么"玄乎"、看起来夺人眼球。**问题：题目范围/表述太宽泛、太不客观。**

**案例② "PERT: adaPtive Evidence-driven Reasoning neTwork for Machine Reading Comprehension with Unanswerable Questions"：** 给模型起名字、用关键词首字母缩写本身没有问题，但这位同学的做法是"从模型名字里若干个单词的不同位置抽取字母拼在一起"（即 PERT 中的大写字母 P-E-T 分散取自 adaPtive、Evidence、neTwork 等单词的**非首字母位置**），并在标题里把这些字母刻意大写以突出名字来源。于静老师指出这样做**非常不规范**：起模型名字，第一要朗朗上口，第二一定要合理——最好是连续的首字母，而非这种间断、跳跃的构词方式，既不规范也不利于读者理解和记忆。

**案例③ "Understanding like humans: multimodal representation for the visual information in visual dialog"：** 这是于静老师自己一篇论文最早的题目，审稿人给出的意见是：人类到底是怎么理解、怎么思考的，学界并没有一个统一的共识（现有科研并未证实这类结论）。这类未被证实的结论**可以**作为论证方法思路的依据（引用已发表论文支撑），但**不能**写进标题——标题必须是客观、科学、准确的，非常主观又缺乏客观依据的说法绝对不要出现在标题里。

**案例④ "Graph Neural Networks for Image-Text Matching"：** 结构、语法都没有问题，看起来也满足前述几点要求。但于静老师指出：如果这个工作出现在 2016、2017 年（图神经网络刚刚兴起的时候），把这个技术应用到图文匹配任务上，这个题目是足够满足需求的；但图神经网络和图文匹配都已经发展了这么多年，再用这样一个题目作为创新性的体现就非常不够了——审稿人看到这个题目的第一印象就是"根本看不出这篇论文核心的创新性在哪里"。**问题：技术过于宽泛/陈旧，未能体现具体的增量创新。**

**案例⑤ "A Plug-and-Play novel Tree Loss Function for Unbiased Scene Graph Generation based on Upgraded Transformer framework"：** 这是大家常见的问题——总想把论文里很多技术上的方法和细节都描述进标题（即查即拔的新颖损失函数、场景图生成去偏、更新的 transformer 框架等）。于静老师指出：**太多细节会干扰真正核心的创新**；不需要在标题里面面俱到，应该在总结论文创新性时，只列出最关键的一两个创新点并凝练在标题里。

**案例⑥ "KBGN: Knowledge-Bridge Graph Network for Adaptive Vision-Text Reasoning in Visual Dialogue"：** 整体结构没有太大问题，于静老师用它解释：给模型起名字时希望起一个既好读又容易记的名字，但"KBGN"这个缩写既没有实际含义，也不朗朗上口——虽然给模型起了名字，但并不利于传播。**问题：缩写生僻、不易记忆传播。**

标题：**一篇论文的组成——标题 (My Own)**

1. *MuKEA: Multimodal Knowledge Extraction and Accumulation for Knowledge-based Visual Question Answering* (CVPR 2022)
2. *ET-BERT: A Contextualized Datagram Representation with Pre-training Transformers for Encrypted Traffic Classification* (WWW 2022)
3. *CogTree: Cognition Tree Loss for Unbiased Scene Graph Generation* (IJCAI 2021)
4. *DualDV: An Adaptive Dual Encoding Model for Visual Dialogue* (AAAI 2020)
5. *Mucko: Multi-Layer Cross-Modal Knowledge Reasoning for Fact-based Visual Question Answering* (IJCAI 2020)
6. *DAM: Deliberation, Abandon and Memory Networks for Generating Detailed and Non-repetitive Responses in Visual Dialogue* (IJCAI 2020)

### 课堂讲解

> 那我们来看一些好一点的例子，这些都是我们大概在近一两年、两三年发表在这个 CCF-A 类会议上面的论文。

于静老师说明，这些题目都是按照前述思路起的：首先给它起一个明确、易传播的名字（模型名，PPT 中原以深绿色标出），后面每个题目都包含"到底解决了什么问题"以及"到底用什么样的方法解决这个问题"两层信息。她重点举了两个例子：

- **MuKEA（CVPR 2022）：** 解决的问题是"知识型视觉问答"；方法上最大的区别和创新性，是用了一种"多模态知识抽取和积累"的方式去解决这一问题。
- **ET-BERT（WWW 2022）：** 是在网络流量、网络加密流量上做预训练模型的工作——"这个在以前是从来没有人说，在看不见内容、不知道语义的情况下，怎么样去做预训练"；本身任务是加密流量分类，方法上用了一种基于预训练 Transformer 架构、面向数据报文的上下文表示方式做分类任务。她强调："起题目的时候，你一定要想到现有这个技术的能力边界，以及你做的这个事在突破这个能力边界上，你到底增量的东西在哪里，你需要把这个内容体现出来。"

> 好，那大家可以有时间自己去看看我们的论文，以及对应这个题目到底和论文是怎么样去对应的。

## 六、好标题案例：CV / NLP / ML 顶会顶刊范例（PPT 第 8 页）

### 课堂讲解

> 那除了我们自己的论文，其实大家可以多去看一下计算机视觉、自然语言处理和机器学习这些顶会顶刊上面好的论文，你可以看到，其实这些论文起题目的时候，真的完全能够非常优秀地满足我们想达到的这些目标。

于静老师逐一简要点评了列表中的代表性例子：

- **DALL·E（Zero-Shot Text-to-Image Generation）：** 简洁且有创新性，解决的是"文本到图像生成"任务，但其最核心、最大的能力体现是 **zero-shot** 能力——完全没有见过某个文本-图像对的情况下，随便给一个文本就能生成对应图像，这是最大的创新性。
- **Swin Transformer（获 ICCV best paper）：** 于静老师提到这是"雅（华）人胡瀚老师他们做的"工作（Microsoft Research Asia，Han Hu 团队），首先起了一个特别朗朗上口的名字；其创新性是提出用层级式（hierarchical）的视觉 Transformer 架构，核心的提效方法是 **shift windows**（移动窗口）。
- **"Sketch, Ground, and Refine"（CVPR，dense video captioning）：** 把核心方法过程完全用三个单词概括（Sketch, Ground, Refine），解决的任务是密集视频描述（dense video captioning），思路是 top-down（自顶向下）。

> 所以大家仔细去分解一下，上面是 CV 的工作，下面还有 NLP 的、还有 machine learning 的，大家去分解一下，看看其实把这个模板给它定义出来之后，你的论文就想办法一定要填出来对应这个模板里面的这些内容。

## 附录：本讲核心概念速查

1. **立意决定论文层级：** 科学问题是否探究本质（前沿/共识 vs. 热点/表面），从"要不要做"这一步就决定了 A/C 类论文的天花板。
2. **A 类 vs C 类三层差异：** 问题（有理有据 vs 跟风）→ 方法（针对问题环环相扣 vs 技术报告式罗列）→ 实验（逐一论证动机与方法 vs 只摆结果不分析）。
3. **一篇论文的九大组成部分：** 标题、摘要、引言、相关工作、研究方法、实验分析、总结展望、致谢、参考文献——各部分边界与侧重点将在后续讲次展开。
4. **标题四要素：** 反映核心问题 / 突显技术创新（具体而非笼统）/ 保护知识产权（可通过模型命名）/ 易于传播记忆。
5. **标题六大反面案例：** 范围过大空泛、缩写非首字母拼凑、主观未证实断言、技术过于陈旧宽泛、细节堆砌掩盖核心创新、生僻缩写不利传播。
6. **好标题模板：** [模型名（朗朗上口）] : [方法核心创新] for [具体任务/问题]，并需在标题中体现相对于现有技术能力边界的具体增量。
