## 0. 本讲一句话

本讲继续讲“论文模型框架图怎么画”，重点不再停留于普通框架图的整洁，而是讨论当论文贡献类型发生变化时，框架图应如何重新分配篇幅、视觉重点和解释逻辑：**新框架要讲清跨领域迁移后的新过程，复杂模型要让模块与信息流清晰，只有 loss 等局部创新时要把创新机制画透而不是把既有框架画满**。

---

## 1. 课堂主线

本讲从上一讲的“框架图绘制”自然延伸。上一部分已经讲过最基础、最共性的问题；本讲进入更复杂的情况：方法思路完全不同、贡献形态不同、读者背景不同，此时框架图不能只是“把流程画出来”，而要回答读者最关心的问题。

本讲的三个核心案例是：

| 案例 | 论文/场景 | 贡献类型 | 课堂重点 |
|---|---|---|---|
| 示例二 | **ET-BERT: A Contextualized Datagram Representation with Pre-training Transformers for Encrypted Traffic Classification**，WWW 2022 | 网络安全老任务 + 新框架 + 大模型/预训练 | 在读者不熟悉“流量预训练”的前提下，图必须讲清数据如何 token 化、预训练任务如何设计、下游任务如何微调。 |
| 赏析一 | **DualVD: An Adaptive Dual Encoding Model for Deep Visual Understanding in Visual Dialogue**，AAAI 2020 | 复杂视觉对话模型框架 | 好图不是简单，而是在复杂情况下仍然做到输入输出明确、模块边界明确、信息流清楚、过程具体。 |
| 赏析二 | **CogTree: Cognition Tree Loss for Unbiased Scene Graph Generation**，IJCAI 2021 | 不是提出新框架，而是提出可嵌入现有框架的 loss | 既有模型框架要略画，核心 loss 与去偏置机理要详细画，并用命中核心问题的真实数据贯穿始终。 |

### Slide 2：示例二——网络安全 | 新框架 | 大模型

页面文字内容：

- 示例二：网络安全 | 新框架 | 大模型
- 论文：**ET-BERT: A Contextualized Datagram Representation with Pre-training Transformers for Encrypted Traffic Classification**
- 会议：WWW 2022
- Paper：`https://dl.acm.org/doi/pdf/10.1145/3485447.3512217`
- Code：`https://github.com/linwhitehat/ET-BERT`
- 作者：Xinjie Lin, Gang Xiong, Gaopeng Gou, Zhen Li, Junzheng Shi, Jing Yu\*

课堂讲解重构：

老师先把这个案例和前一个案例区分开来。前一个案例是“提出了一个新的方法或新的解决问题思路，但框架本身没有变”，即输入和输出仍然是相同范式。而 ET-BERT 这个工作是在“加密流量分类”这个老任务上提出完全不同的新框架：**用预训练模型做加密流量分类**。

这里的困难在于，文本和图像领域的预训练模型大家比较熟悉；但加密流量数据不是自然语言，也不是图像，而且它还看不见语义内容。读者在看到这个题目时会自然产生几个问题：

1. 文本/图像预训练模型需要 token 作为输入，那么连续的二进制流量如何被表示成预训练模型能接收的 token？
2. 数据本身看不见内容，预训练任务到底怎么设计？
3. 完成预训练以后，下游任务如何微调？
4. 如果审稿人是 AI 方向专家，他会关心：你在网络流量领域如何实现别的领域已经有的预训练步骤？
5. 如果审稿人是网络安全领域专家但不熟悉 AI 预训练，他会关心：这个新框架为什么能解决通用识别问题？

因此，这类“新框架”论文的框架图有双重任务：既要让不懂新框架的领域读者理解整个框架，又要让懂新框架的 AI 读者看出论文的真正创新在哪里。

### Slide 3：模型框架图 V1——最初版本

页面文字内容：

- 标题：模型框架图 V1
- 中央标注：最初版本
- 主要问题：**太多细节，大量数据预处理，甚至方法对比，毫无重点！**

图的文字化复现：

- 图上方展示网络服务图标、Sniffer、Encrypted、User 等元素，试图从网络服务到用户侧说明流量采集过程。
- 左侧展示 Raw Data、Preprocessing、Labeled Data 等数据流。
- 中部上方用红色虚线区域表示 Pre-training 方案，包含：
  - Large-scale Data without Labeled
  - Pre-Training Model
  - Traffic Representation
  - Small-scale Labeled Data
  - Fine-Tuning
  - 多个 Task 输出
- 下方用灰色虚线区域展示 Traditional Fingerprinting 方法，包含：
  - Feature Selecting
  - Sequence Data / Finger Data / Payload Data
  - Feature Engineering
  - Statistical Features / Transmission Features / Graph Features / Bytes Features
  - ML / CNN / GNN / RNN
  - 多个任务输出

课堂讲解重构：

老师明确指出：这个版本虽然表面上看起来规范、复杂、完整，但实际上非常不成功。原因不是画得不美观，而是内容没有服务论文要表达的核心问题。

这个版本存在三个根本问题：

1. **数据预处理细节过多**。大量空间都在展示 raw data、preprocessing、labeled data 等过程，但这些不是读者最想知道的创新。
2. **把传统方法对比放进了模型框架图**。传统 fingerprinting 怎么做，更适合放在 motivation 或 related work 中，而不是在模型框架图中与本文方法占据相近篇幅。
3. **没有回答审稿人最关心的问题**。读者真正想知道的是：加密流量怎样变成 token？预训练任务怎样设计？微调怎样进行？这个图没有突出回答这些问题。

课堂强调：不要被图的“表象”影响。框架图不是越复杂、越满、越像系统工程图就越好；关键是有没有体现出论文需要传达给审稿人和读者的核心问题。

### Slide 4：模型框架图 V2——明确输入、输出、主要过程

页面文字内容：

- 标题：模型框架图 V2
- 中央标注：明确输入、输出、主要过程
- 主要问题：**模块冗余，毫无说明，过程逻辑不清晰！**

图的文字化复现：

- 左侧有模块图例：Pre-training Tasks、Encoder Transformer × N、Embedding、Tokenization、Unlabeled Raw。
- 中央左侧展示 Pre-training 部分：输入 token 序列经过 tokenization、embedding、transformer 等层，顶部连到 MLM、DLS、FLS 等任务。
- 中间存在 Shared Model，并将左侧预训练与右侧 fine-tuning 相连。
- 右侧展示 Fine-tuning 部分：输入 labeled raw，经过 tokenization、embedding、encoder transformer、pooling、linear、softmax，顶部输出 classifier。

课堂讲解重构：

这一版比 V1 有进步，因为开始体现“预训练”和“微调”的过程。但是老师指出，这个图仍然“没有信息量”。虽然图中填满了各种颜色、各种小块、各种箭头，但读者仍然看不出：

- 这篇工作的创新是什么？
- 它在流量数据上解决了什么特有问题？
- 与既有预训练模型的区别在哪里？
- 这些符号、层次、模块名称有什么领域特异性？

老师强调：在真正画图之前，作者必须先回答几个问题，并把答案写下来：

1. 我这个图到底要回答哪几个创新问题？
2. 我到底做了什么创新点？
3. 这个创新点通过哪个过程实现？
4. 哪些过程是必要背景，哪些过程是本文贡献？

只有先确定目标，才能“有目标地画图”，而不是想到什么就画什么。

### Slide 5：模型框架图 V3——划分主要模块，明确模块功能

页面文字内容：

- 标题：模型框架图 V3
- 中央标注：划分主要模块，明确模块功能
- 主要问题：**技术创新不明确，训练、微调过程不清晰！**

图的文字化复现：

图被拆成三块：

1. **Datagram2Token**
   - 从 PCAP Traces 出发。
   - 经过 Flow-based Splitting、Packet-based Splitting、Separate Packets、Reorganize 等步骤。
   - 形成 BURST、Hexadecimal Datagram、Bigram Tokenization、BURST Tokens、Half-splitting、sub-BURST Pairs。
2. **Encrypted Traffic BERT (ET-BERT)**
   - 展示输入 token embedding、position embedding、segment embedding。
   - 中央是 Transformer-based Profiling。
   - 顶部输出若干 token 表征。
3. **Pre-training Self-supervised Tasks**
   - 包含 Masked Language Model / Fully Masked。
   - 包含 Sequential Structure，如 Datagram Level Byte Reordering、Flow Level Packet Reordering。
   - 包含 Adjacent Structure，如 Packet Distance。

课堂讲解重构：

V3 的主要进步是“三个过程已经清晰”：

- 数据如何从原始数据处理到预训练模型能接收的数据；
- 预训练模型大致如何工作；
- 最后如何进入微调。

但老师仍然指出它的问题：真正创新的位置没有被清晰表达。对于预训练模型来说，最创新的部分往往是**预训练任务怎么设计**。V3 虽然用大量颜色和模块展示了流程，但最吸引注意力的地方反而没有信息量；训练过程和微调过程也没有让人一眼看出“新在哪里”。

课堂提醒：人的注意力会被色彩最鲜艳、视觉最突出的元素吸引。因此视觉强调必须与论文创新对齐。如果把最亮的颜色放在无关细节上，图就会误导读者。

### Slide 6：模型框架图 V4——20+ 次修改后的最终版本

页面文字内容：

- 标题：模型框架图 V4
- 中央标注：**20+ times later … 最终版本！**

图的文字化复现：

最终图被清晰分为三大区域：

#### 1. Datagram2Token

左侧区域又分成两条子流程：

- **BURST Generator**：
  - PCAP Trace
  - Flow-based Splitting
  - Session Flow
  - Packet-based Splitting
  - Separate Packets
  - Reorganize
  - BURST
- **BURST2Token**：
  - Hexadecimal Datagram：示例为 `451dd0 ... 583c0d`
  - Bigram Tokenization
  - BURST Tokens：示例为 `451d 1dd0 ... 583c 3c0d`
  - Half-splitting
  - Sub-BURST Pair：示例为 `451d 1dd0 ...` 与 `... 583c 3c0d`

#### 2. Pre-training

中间区域标题为 **Pre-training**，核心模型标为 **ET-BERT**。图中弱化了 transformer 内部细枝末节，用半透明方式展示内部结构，以避免无关细节抢占注意力。

预训练部分明确展示两个任务：

- **Same-origin BURST Prediction**
- **Masked BURST Model**

输入层展示：

- Token Embedding，如 `[CLS]`、`451d`、`009c`、`[SEP]`、`[MASK]`、`583c`、`[PAD]`
- Position Embedding，如 `1`、`2`、`K-2`、`K-1`、`K`、`K+1`、`M`
- Segment Embedding，如 `A`、`B`
- Sub-BURST A 与 Sub-BURST B 的划分

#### 3. Fine-tuning

右侧区域标题为 **Fine-tuning**，以多个堆叠任务页表示不同下游分类任务：

- Tor Classification
- VPN Classification
- Apps Classification

每个任务都使用 ET-BERT 作为主体，并以 Datagram A 的 token/position/segment embedding 作为输入，顶部输出分类结果。

课堂讲解重构：

老师认为最终版相对清晰、完善，原因在于：

1. **数据预处理过程被命名并具象化**。每一步叫什么、从原始输入到每一步处理后的样子，大致长什么样，都直观展示出来。
2. **模型主体被明确命名**。图中清楚告诉读者整个模型主体叫 ET-BERT，而不是让读者在一堆 transformer 细节中猜测。
3. **预训练任务被放在显著位置并命名**。输入是什么、输出任务是什么，都与正文中的内容一致。
4. **微调过程与领域任务建立关系**。微调不是抽象地“fine-tune 一下”，而是针对 Tor、VPN、Apps 等不同流量分类任务进行微调，领域读者能理解其必要性。
5. **不重要的内部细节被弱化**。最终版本不再让无关小块、无关颜色吸走注意力，而是用透明度和层次把重点让出来。

从 ET-BERT 这个案例，老师总结出一种新框架图的难点：图既要让领域内读者理解从无到有的新框架，又要让懂新框架的人看见本文独特创新在哪里。

### Slide 7：DualVD 框架图——提出问题

页面文字内容：

- 标题：模型框架图
- 论文：**DualVD: An Adaptive Dual Encoding Model for Deep Visual Understanding in Visual Dialogue**（AAAI 2020）
- 提问：一起赏析下这个图好在哪里？

图的文字化复现：

这张图展示视觉对话任务的完整模型框架。左侧是输入，右侧是输出，中间是视觉模块、语义模块和融合模块。

输入包括：

- 当前问题 `Current Question Q`：示例句子为 “Is he wearing shorts?”
- 对话历史 `Dialogue History H`：包含若干问答，如 “Is he young or old?”、“Young, late teens.”、“Is he in mid-air?”、“Yes.” 等。
- 图像 `Image I`：画面中有人在滑板场景中做动作。
- 图像描述 `Image Caption C`：例如 “A man doing a trick on his skateboard on a wall.”
- Dense Caption `Z`：例如 “The man is wearing black pants.”、“Skateboard in the air.”、“The boy is wearing a shirt.”
- 答案候选 `Answer Candidate A`

模型过程包括：

- 当前问题和对话历史分别经过 LSTM 得到 question embedding 等表示。
- 图像经过 Faster R-CNN 得到 object regions。
- 视觉模块包含：
  - Visual Relationship Encoder
  - Question-Guided Relation Attention
  - Question-Guided Graph Convolution
  - Object-Relation Feature Fusion
  - Visual Embedding
- 语义模块包含：
  - Question-Guided Semantic Attention
  - Global-Local Feature Fusion
  - Caption Embedding
- 视觉知识与语义知识通过门控或融合节点形成 Visual Knowledge Embedding。
- 底部还有当前问题、对话历史、候选答案的 LSTM 编码与 Late Fusion。
- 输出为 Answer Candidates 的 Score，如 `A1 0.20`、`A2 0.05`、`...`、`A100 0.03`。

课堂讲解重构：

老师让大家先“赏析”这个图为什么好。虽然这个图本身看起来复杂，但它的复杂不是混乱，而是每一块都能找到对应作用，每条线都服务信息流转。

### Slide 8：DualVD 框架图——好在哪里

页面文字内容：

- 论文：DualVD: An Adaptive Dual Encoding Model for Deep Visual Understanding in Visual Dialogue（AAAI 2020）
- 总结：
  - 模块划分清晰
  - 输入、输出明确
  - 过程准确具体

图中红色标注强调：

- 左侧输入、右下角输出明确。
- Visual Module 和 Semantic Module 的模块划分清晰。
- 视觉路径中的具体过程、语义路径中的具体过程都被明确标出。

课堂讲解重构：

老师总结这个图清晰的原因：

1. **输入输出明确**。读者能一眼看到输入是什么、输出是什么。
2. **不同信息流用不同视觉路径表达**。视觉信息和语义信息采用不同颜色或区域，分别进入不同模块。
3. **同一路径下的关键过程被相同背景和明确名称组织起来**。例如视觉模块中从 object regions 到关系编码、注意力、图卷积、融合，路径连续而不混乱。
4. **具体过程的作用被可视化**。图中节点、边、文本示例都在帮助读者理解“这一步到底在做什么”。
5. **示例内容经过选择**。框架图是示意图，不是原始数据的完整复刻。作者只需要把最能达到解释目的、最直观、最简洁的部分放出来。

本页最关键的课堂提醒是：画图不是把所有真实内容全部放进去。示意图的任务是用最少的、最恰当的内容达到解释目的。对于图像内容，如果难以直接表达，就要选择合适的抽象形式；对于文字内容，如果容易举例，就要选特别直观、简洁的例子。

### Slide 9：CogTree 框架图——提出问题

页面文字内容：

- 论文：**CogTree: Cognition Tree Loss for Unbiased Scene Graph Generation**（IJCAI 2021）
- 提问：这个图又又又好在哪里？

图的文字化复现：

图分为三个主要区域：

1. **上方：Bias-Based CogTree Building**
   - Step 1: Bias-Adaptive Concept Induction
     - 以关系类别如 On、Parked on、Standing on、Walking on、Near、In front of、Behind 等为例，用条形分布展示偏置关系。
   - Step 2: Concept-Centered Subtree Building
     - 以 parked on、on、standing on、walking on、near、in front of、behind 等关系词为节点构建子树。
   - Step 3: Cognition-Based Subtree Aggregation
     - 将多个子树聚合成包含若干关系概念的树结构。
2. **左下：Input Image 与 Scene Graph Generation Network**
   - 输入图像中有多个目标框。
   - Scene Graph Generation Network 包含 relation encoder、relation decoder、object encoder、object decoder 等。
   - 该部分展示的是清晰的模型框架，但并非本文创新点。
3. **右下：Debiasing CogTree Loss**
   - 通过几个三维空间示意和树结构示意展示 loss 如何影响关系类别分布。
   - 重点展示去偏置机制和每一步操作后的分布变化。

课堂讲解重构：

老师先指出这个工作的贡献不是提出一个新框架，也不是在框架中改进某一个大模块，而是提出一个 loss。这个 loss 位于模型最后输出部分，而且可以作为通用 loss 用到任何符合该任务框架的模型上。

这种论文的图很容易犯错：作者往往会用大量篇幅讲现有任务框架第一步、第二步、第三步怎么做，读者看了大半页以后才发现那根本不是本文贡献。

因此老师强调：如果你的创新是 loss，那么图和正文都不应该把重点放在既有框架上。你可以在 Methodology 开头先说明：我的 loss 是通用的；在已知输出形式的情况下，我先定义并解释 loss 如何计算；最后再说明这个 loss 如何与现有框架结合。这样写不一定要按照模型从头到尾的执行顺序，而要按照创新表达的逻辑顺序。

#### 原则 1：明确输入、输出、关键过程

这是框架图最低限度必须做到的事。读者应该在第一眼知道：任务输入是什么，输出是什么，中间关键过程有哪些。

#### 原则 2：突出创新，避免罗列非本文贡献内容

图的最大篇幅，无论是视觉篇幅还是文字篇幅，都应该服务创新点，而不是服务你实际做实验时花了最多时间的步骤，也不是机械按照方法从头到尾的执行顺序展开。

#### 原则 3：划分模块，明确各模块所解决问题

每个模块都应该回答：它解决中间哪个环节的问题？为什么它能解决这个环节？模块边界不只是排版问题，而是逻辑问题。

#### 原则 4：精准命名每个过程、变量、符号

图中的模块、变量、符号、输入输出过程都要有清晰准确的命名。不要凭个人感觉重新命名已有共识概念，因为重新定义名字会增加额外解释成本。能用领域共识符号和图形表达时，应优先使用它们来降低沟通成本。

#### 原则 5：一致表达图示和正文相同语义内容

一致性包括两层：

- 同一张图中，前后表达相同内容的符号和视觉形式要一致。
- 正文与图中的命名、符号、变量、过程名称要一致。

## 3. 完整课堂讲述整理稿

> 以下根据当前讲次 transcript 整理，保留口语逻辑和课堂顺序，仅补充段落、标点与必要术语规范，使其成为可阅读的课堂讲稿。

### 3.1 从上一部分过渡到本讲

刚才我们花了很长时间把第一个例子讲完了。因为那里面出现的问题，都是最基础、最共性的问题。后面我还会讲一些例子，但相关的、相同的、类似的问题就不会重复展开。我会讲一些新的问题，也就是在方法思路可能完全不同的情况下，这个图到底怎么画才合适。

刚才那个图的思路是：我们提出了一个新的方法，提出了一个新的解决问题思路；但是框架其实并不新，因为仍然是同样的输入和输出。而现在这个工作，是在加密流量分类这个老任务上提出了一个完全新的框架，也就是用预训练的方法。之前其实没有人在完全不知道语义、看不见内容的数据上面做预训练。

读者看到这个题目，并且和你抱有相同疑惑时，他最想知道什么？在文本和图像预训练中，模型需要把内容表示成预训练模型能接收的 token 形式。那么连续的二进制流量，怎么做这种语义表示？这是第一个问题。

第二个问题是：这种看不见内容的数据，到底怎样设计预训练任务？然后，下游任务又怎样微调？这不就是预训练最关键的三个过程吗？换了一个领域，换成一种大家完全不能理解的数据，你肯定要把这三个过程详细讲清楚。

同样地，如果你的论文提出了一个新的框架，而这个框架在其他领域其实已经有大量成果，那么审稿人看到之后会有两类疑问。尤其是 AI 审稿人，他首先会问：你在这个领域里，如何做到其他领域中已有框架的相同步骤？如果他不是 AI 专家，只是这个领域中知道传统方法的人，他可能对整个框架都不了解。你怎样让他接受这个框架能解决通用识别问题？这非常难，因为你是在认知上为他打开一扇新的窗户。

所以，你不知道审稿人来自什么知识背景、处于什么水平。这些都要考虑进你怎样把内容表达清楚。

### 3.2 ET-BERT V1：看起来规范，但没有抓住内容

第一版本非常混乱。虽然它看起来很规范，但大家不要被表象影响。画图时一定要关注内容：你有没有体现出要向审稿人和读者传达的几个核心问题？这个版本完全没有。

图中大量都是数据处理过程，甚至还有一大块灰色部分，把传统方法怎么做也放进来与本文方法对比。这个东西其实应该在 motivation 中讲，而不是放在模型框架图里。因此这个版本虽然看起来很好看，但非常不成功。

### 3.3 ET-BERT V2：把训练和微调画出来了，但仍然没有信息量

到下一版本，我希望作者把那几个过程体现出来，比如训练、微调。这一版确实画出来了，但是你会发现内容几乎没有任何信息量。虽然整个块都填满了，各种颜色、各种小块都有，但读者看不出创新是什么。

你在流量上怎么解决这些问题？虽然举了具体例子，但方法是什么？完全没有体现。而且符号定义、层次过程的命名，与现有方法没有区别，没有体现出这篇工作的创新之处。

所以，在真正画图之前，大家一定要先回答几个问题，并写下来：这个图到底要回答哪几个创新问题？我到底做了什么创新点？这个创新到底通过哪个过程实现？然后再画图，才是有目标地画，而不是想到什么就画什么。

### 3.4 ET-BERT V3：三个过程清楚了，但创新仍然不突出

到下一个版本，至少它的三个过程已经清晰：数据处理，怎样从原始数据到预训练模型能接受的数据；预训练模型的过程；最后到微调。

但是大家会发现，预训练最创新的地方其实是：到底设计了什么预训练任务。图中虽然用了大量颜色，尤其是某一块最鲜艳，但那一块没有信息量。人的注意力会被色彩最鲜艳的地方吸引，如果最鲜艳的地方没有信息量，就会造成误导。

后面的预训练部分也是这样：到底新在哪里？与现有微调方法的差别在哪里？表达得很不清晰。作者其实想表达用了不同的微调方式，但图中没有说清楚。

### 3.5 ET-BERT V4：20 多个版本之后的清晰版本

这个图也是经历了二十多个版本的大修小修，最后才画出来。我觉得最终版相对清晰和完善。

比如，它把数据预处理过程中的每一步叫什么命名出来了；从原始输入到每一步处理之后大概长什么样，也能直观展示。这个非常好。

接着有了输入之后，在预训练模型里，它知道不要突出那些没用的东西，而是用透明度把内部细节弱化出来。同时，它给模型命名，告诉读者整个模型叫 ET-BERT。输入关键是什么，输出的预训练任务是什么，都清晰定义了名字，并且与论文正文中的内容一致。

微调过程也一样：它把微调的作用画出来。为什么微调有用？因为它针对不同流量、不同分类任务做微调，这与领域相关。读者看到 Tor Classification、VPN Classification、Apps Classification 这样的名字就能理解。

这个版本做得很好。这个案例其实是另一种框架图：论文提出了一个新框架，因此图中既要让读者知道框架的整个过程，因为领域读者原本没有这种框架印象；又要让知道这个框架的人看出创新之处在哪里。这挺难，需要慢慢练习。

### 3.6 DualVD：复杂但清晰的框架图

通过前面两个从零到一的详细过程，我们理解了框架图要注意哪些关键问题。下面一起赏析一个图，这是发表在 AAAI 2020 上的 DualVD。

这个图画完之后，大家会觉得过程很清晰。虽然它看起来过程复杂，但每一块，不管用框还是箭头，都能清晰表达。它为什么让人觉得清晰？

首先，它输入输出很明确，输入是什么样子，输出是什么样子，都很清楚。

第二，它把不同信息流转路径用不同颜色或不同区域表示出来。在同一路径下面，不同关键过程和模块用相同背景组织起来，但不同名字又划分得很清楚。另一条路径也同样清楚地划分出来。

第三，它把具体过程的作用表达出来。无论是图上节点和边的颜色，还是根据图得到的具体文字内容，都能给出清晰、直观的表达。

所以大家一定要动脑子想：如果内容是图像的，不好表现，那用什么形式表现？如果内容是文字的，比较好举例，那是否能找到特别恰当、直观、简洁的例子？图里放的这些文字未必是原始数据的全部文字，只要把最直观、最好理解的部分写出来就可以。

画图时还有一个误区：示意图不是一个真实例子的全部内容。你只需要把能够达到解释目的的那部分内容画出来。

### 3.7 CogTree：当贡献只是一个 loss 时，框架图要换重心

接下来赏析另一个图，这是发表在 IJCAI 2021 上的 CogTree。这个工作的创新之处并不是提出一个框架，也不是在框架中改进某一个过程，而只是提出一个 loss。这个 loss 是整个模型最后输出部分要用的，而且可以通用地用在任何符合这个框架的模型上。

这种图在写作时很容易出错。我们同学第一版写的时候就有这个问题：花了大量篇幅把以前的框架，也就是任务本身第一步、第二步、第三步怎么做，写得特别清楚。读者看了大半页，发现根本不是作者自己做的东西。

所以，在画图时，重点肯定不是既有框架，重点应该是你要突出的东西，比如损失函数怎样实现。

在写论文时，也不一定要按照“先怎么样、再怎么样”的执行顺序来写。如果你的 loss 是要突出的东西，但位于整个过程最后面，那么可以在 methodology 开头就说明后文组织逻辑：我的 loss 是一个通用 loss；我首先在已知输出形式的情况下定义输出形式，然后讲这个 loss 怎么计算、怎么设计；最后再讲这个 loss 怎么与现有框架结合、怎么与不同方法结合。而“怎么结合”不是你的创新，只是告诉别人你的东西怎么用。

所以，不管是在图里还是正文里，它都不应该占最多篇幅，也不一定要按照从头到尾的顺序写。

### 3.8 CogTree 图的关键优点

这个图中，左下角清楚画出了模型框架，但它不是创新点，所以略画。真正核心技术在上方和右下方，需要详细画。

对于方法复杂、不好理解的内容，一定要举一个与审稿人最直观、与核心问题最相关的真实数据，并贯穿方法始终。这样读者能直观理解方法到底在做什么。

正文可能会有复杂操作和很多公式，但公式最后输出的效果是什么样，要在图里直观体现。每一步效果之间要有衔接：前一个过程输出了某个东西，后面基于这个东西组合出另一个东西，读者就能自己脑补中间过程。这会省去大量正文中可能说不清的内容，这就是画图最大的作用。

如果测试过程和训练过程不一致，也要分开讲。

这个图还做得很好的一点是：它告诉读者方法背后在数据分布上为什么能达到去偏置效果。通过形象地展示空间里这些点在每一步操作时的分布变化，读者可以直观看到方法的道理和效果。

所以大家一定要知道：画的图不只是过程的重复展现，而是要用不同手段表达背后的道理和效果。

### 3.9 全讲总结

前面举了几个例子，代表了几类创新方法。不同 contribution 的图可能不一样，但基本原则是共同的。

首先，必须明确输入、输出和关键过程，这是框架图最基本要体现的东西。

第二，要明确创新之处是什么，并用最大的篇幅去突出。不管是图像篇幅还是语言篇幅，都要围绕创新，而不是按照你做的过程中花最多时间的部分，或者按照方法从头到尾的顺序来分配。一定要围绕创新、围绕你解决的问题展开。

第三，要划分模块。每个模块解决中间哪个环节？为什么能解决这个环节？要非常清楚地展示。

第四，要给图中所有模块、输入输出过程、变量和符号清晰准确的命名。不要凭个人感觉命名。你一定要知道领域共识，因为重新定义名字就需要花大篇幅解释；使用大家有共识的符号和图形，可以降低沟通成本。

最后，一定要一致。同一张图中，前后表达相同内容的符号要使用相同表现形式；正文与图中的命名、符号、文字也要一致。

| 论文贡献类型 | 图中应该最大篇幅画什么 | 图中应该弱化什么 | 读者最关心的问题 | 典型错误 |
|---|---|---|---|---|

| 训练与测试不同 | 分开展示 training 与 inference/test 的不同路径 | 把两个过程混成一条流程 | “训练时用的信息，测试时是否还存在？” | 读者无法判断论文是否有信息泄漏或不一致设置。 |
| 跨领域借鉴方法 | 本领域数据与原领域数据的差异，以及为适配差异做的改造 | 原领域通用流程 | “你做的不是简单迁移，改造点在哪里？” | 模块名、符号、流程都与原方法一样，看不出本文贡献。 |

## 5. 可直接使用的绘图前自问清单

在开始画模型框架图前，先写下这些问题的答案。

### 5.1 关于读者

1. 审稿人可能来自哪些背景？领域专家、AI 专家、交叉领域专家分别会困惑什么？
2. 哪些概念对你来说很熟悉，但对读者来说是第一次见？
3. 哪些步骤如果不画清楚，读者会不相信这个框架能成立？

### 5.2 关于贡献

1. 本文贡献是新框架、新模块、新训练任务、新 loss、新数据表示，还是新应用场景？
2. 图中最大篇幅是否给了真正贡献？
3. 图中是否罗列了很多非本文贡献内容？
4. 如果删掉某个模块，是否会影响读者理解创新？如果不会，就应该弱化或删除。

### 5.3 关于过程

1. 输入是什么？输出是什么？中间关键过程是什么？
2. 每个模块解决什么问题？为什么能解决？
3. 每一步输出是否能自然连接下一步输入？
4. 训练过程与测试/预测过程是否一致？不一致时是否分开画？

### 5.4 关于表达

1. 图中命名是否与正文完全一致？
2. 同类元素是否使用一致的符号、颜色、线型和排版？
3. 颜色最醒目的地方是否就是最重要的创新点？
4. 示例是否足够直观、简洁、命中核心问题？
5. 图是否在表达背后的道理和效果，而不只是重复流程？

---

## 6. 本讲的反面模式清单

1. **漂亮但无效**：图看起来规范、复杂、颜色丰富，但读者看不出创新。
2. **预处理喧宾夺主**：大量篇幅花在数据清洗、格式转换、采集流程上，真正贡献被挤到角落。
3. **把 Motivation 放进 Framework**：传统方法对比、问题背景、动机说明过多，占据框架图空间。
4. **模块堆叠无说明**：transformer、embedding、pooling、softmax 等模块都有，但没有说明为什么这样设计。
5. **创新命名缺失**：关键任务、关键变量、关键机制没有自己的准确名称，导致正文和图无法互相锚定。
6. **颜色误导**：最鲜艳的区域不是创新点，读者注意力被带偏。
7. **既有框架画太满**：当贡献只是 loss 或训练策略时，却把通用 backbone 画成主角。
8. **示意图当真实数据全量复刻**：试图把所有真实内容放进图中，导致拥挤且不聚焦。
9. **训练测试混杂**：训练时使用的额外结构、标签或统计信息与测试时流程不同，却没有区分。
10. **图文不一致**：图中的模块名、符号名与正文不同，增加读者认知负担。

---

## 7. 本讲知识压缩为一句工作法

> 画模型框架图时，不要问“我做了哪些步骤，所以我要都画出来”，而要问“审稿人要相信我的贡献，必须理解哪几个关键问题；我应该用多少篇幅、怎样的模块边界、怎样的命名和示例，让这些问题一眼被回答”。

**关于审稿人背景的不确定性：** 如果框架在其他领域已有大量成果，AI 背景的审稍人会问"你怎么做到在其他领域做不到的、相同的过程步骤？"；如果审稿人不是 AI 专家、只了解传统方法，那么他对整个框架都不了解，你需要"在认知上给他打开一个新的窗户"，让他接受这个新框架能解决通用的识别问题——这是非常难的一件事。**你不知道审稿人来自什么样的知识背景和水平，所以都要考虑在如何清晰表达内容之中。**

## 一、框架图演化实录：ET-BERT（PPT 第 2–6 页）

### 幻灯片内容（PPT 第 2 页，与第六讲第 10 页同源，原文精准转录）

标题：**示例二：网络安全 | 新框架 | 大模型**

> **ET-BERT: A Contextualized Datagram Representation with Pre-training Transformers for Encrypted Traffic Classification**
> **WWW 2022** ｜ Paper: https://dl.acm.org/doi/pdf/10.1145/3485447.3512217 ｜ Code: https://github.com/linwhitehat/ET-BERT
> 作者：Xinjie Lin, Gang Xiong, Gaopeng Gou, Zhen Li, Junzheng Shi, Jing Yu*

### V1（PPT 第 3 页）：最初版本

**主要问题（页面原文）：** 太多细节，大量数据预处理，甚至方法对比，毫无重点！

### 课堂讲解

> 他第一版本，我觉得这个版本其实是非常混乱的哈，就虽然他画图看起来很规范，大家不要被表象影响，画图的时候一定要关注内容。

于静老师特别提醒：这一版"看起来很好看"，但**内容上完全没有体现要传达给审稿人和读者的关键问题**。大量篇幅是数据处理过程，甚至有一大块灰色部分专门画传统方法怎么做（作为对比）——但这部分内容其实应该放在 motivation 里讲，不该出现在框架图里。**"虽然看起来很好看，但是一个非常不成功的版本。"**

### V2（PPT 第 4 页）：明确输入、输出、主要过程

**主要问题（页面原文）：** 模块冗余，毫无说明，过程逻辑不清晰！

### 课堂讲解

于静老师要求学生把训练、微调等过程体现出来，学生确实画出来了，但**内容完全没有任何信息量**——虽然把整个画面块都填满了、用了各种颜色和小块，但看不出创新是什么、在流量问题上到底怎么解决的；符号定义、各层次过程的名字，和现有方法比也没有任何区别，**没有体现出这篇工作的创新之处**。

> 所以我想说，在大家真正画图之前，一定要回答自己几个问题，把它写下来：我这个图到底要回答哪几个创新的问题？我到底做了什么样的创新点？我这个创新到底是怎么样通过哪个过程去实现的？先想清楚这些，再画图才有目标，而不是想到哪画到哪。

### V3（PPT 第 5 页）：划分主要模块，明确模块功能

**主要问题（页面原文）：** 技术创新不明确，训练、微调过程不清晰！

### 课堂讲解

这一版至少把三个过程（数据处理成预训练模型能接受的输入 → 预训练模型的过程 → 微调）理清楚了。但问题在于：**真正的创新之处（预训练任务到底设计了什么）反而用了大量花哨的颜色**——"人的注意力肯定会被色彩最鲜艳的地方吸引，而偏偏色彩最鲜艳的这些地方一点信息量都没有"。后面的微调部分也很奇怪，学生本想表达用了不同的微调方式，但表达得非常不清晰。

### V4（最终版本，PPT 第 6 页）

**幻灯片标注（原文，含英文"20+ times later..."字样，确认修改总版本数超过 20 次）：** 图中清晰展示 BURST Generator → BURST2Token（十六进制数据示例）→ Pre-training（ET-BERT 模型区域用半透明遮罩突出重点区域，明确标注模型名称"ET-BERT"）→ Fine-tuning（Traffic Classification / Apps Classification 两类下游任务）的完整流程。

### 课堂讲解

> 这个也是一个男生，经过大概二十多个版本的大修小修，最后他真的把这个图画出来了，相对清晰完善。

于静老师逐项肯定这一版的进步：数据预处理的每个过程都命名清楚，并直观展示了从原始数据输入到每一步处理完之后的样貌；预训练模型部分，学生学会了不要突出没用的东西，用有透明度的遮挡处理，把真正的模型区域清晰标注为"ET-BERT"，输入的关键内容和预训练任务的输出都给出清晰定义的名字，与正文内容一致；微调过程也清楚说明了为什么微调有用（针对不同流量或分类任务做微调，与该领域的实际需求相关）——"看的人一看这个名字就理解"。

> 这个其实又是另一种框架图了——你既要让读者知道这个框架的整个过程（因为这个领域的人印象里没有这么一个框架），又要体现出你的创新之处在哪里。这其实挺难的，大家慢慢练习。

## 二、赏析一：DualVD（AAAI 2020）——如何把复杂过程画清晰（PPT 第 7–8 页）

### 幻灯片内容（原文精准转录，来自 PDF 文本层直接提取）

标题：**模型框架图 —— DualVD: An Adaptive Dual Encoding Model for Deep Visual Understanding in Visual Dialogue (AAAI 2020)**

图中展示完整的视觉对话模型框架：Current Question Q → Question Embedding；Dialogue History H；Image 一侧分为 Object Regions（经 Faster R-CNN）与 Dense Caption Z 两条路径，分别通过 Question-Guided Relation Attention → Graph Convolution → Visual Module（视觉模块，绿色标注一致）以及 Question-Guided Semantic Module（语义模块）进行特征融合（Feature Fusion），最终 Late Fusion 后通过 Softmax 得到各候选答案（Answer Candidates A₁, A₂, ... Aₙ）的得分。批注：**"这个图好在哪？"**、**"模块划分清晰"**、**"过程准确具体"**。

### 课堂讲解

> 那我们来一起欣赏一下、赏析一下这个图，这个是我们发表在 AAAI 2020 上的图。这个过程虽然看起来很复杂，但每一块不管是用框还是箭头，都能清晰地把它表述出来。

于静老师总结这张图之所以清晰的三个原因：

1. **输入输出很明确：** 输入是什么样子，输出是什么样子，一目了然。
2. **信息流转路径用不同颜色区分，同一路径下不同关键模块用相同背景色但不同名字清晰划分。** 比如图像这一路用绿色统一标注。
3. **具体过程的作用都能清晰直观地表达出来**——不管是用图上节点和边的颜色，还是用文字展示根据这部分得到的具体内容，都给出了清晰直观的呈现。

> 大家一定要动脑子想：你这个内容如果是图像的，可能不好表现，那用什么形式表现？如果是文字，可以举例子，那能不能找到一个特别恰当、直观、简洁的例子？你放的这些文字未必是原始的全部文字，只要把最直观、最好理解的那部分话写出来就 OK 了。

**重要提醒（画图的常见误区）：** 于静老师特别强调，**框架图是"示意图"（schematic），不是真实内容的完整还原**——不需要把所有原始细节都塞进去，只要把能表现达到目的的那部分内容画出来就足够了。

## 三、赏析二：CogTree（IJCAI 2021）——如何处理"非本文创新"的既有框架部分（PPT 第 9–10 页）

### 幻灯片内容（原文精准转录，来自 PDF 文本层直接提取）

标题：**CogTree: Cognition Tree Loss for Unbiased Scene Graph Generation (IJCAI 2021)**

图分为两大部分：左侧"Input Image → Scene Graph Generation Network → Debiasing CogTree Loss"标注为既有框架（Encoder-Decoder 结构处理 Relation 与 Object，得到 Object and Label Embeddings）；右侧"**Bias-Based CogTree Building**"分为三步详细展开：**Step 1: Bias-Adaptive Concept Induction**（如"parked on / near / on..."等关系概念的偏置自适应归纳）、**Step 2: Concept-Centered Subtree Building**（以概念为中心构建子树）、**Step 3: Cognition-Based Subtree Aggregation**（基于认知的子树聚合），并配有真实图像中"car"相关的关系类别（parked on, walking on, near, in front of 等）贯穿整个三步流程作为具体示例。批注：**"核心技术创新，详细画！且用命中核心问题的真实数据贯穿始终！"**（针对右侧三步）；**"清晰明了的模型框架，但不是创新点，略画！训练过程和预测过程不同，需要分开阐明"**（针对左侧既有框架部分）。

### 课堂讲解

> 这个工作的创新之处并不是提出一个框架，也并不是在这个框架里改进了某一个过程，其实他只是提了一个 loss，这个 loss 可以是通用的，用在任何符合这个框架的模型上面。

于静老师指出这类工作的常见误区（也是学生第一版写作时的问题）：**花大量篇幅把以前的框架（任务本身第一步第二步第三步怎么做）写得特别清楚，读者看了大半页才发现根本不是作者自己做的东西。**

**写法建议：**

1. 画图和写论文的重点，绝对是你自己真正的创新（本例中是 loss 怎么实现），既有框架部分应该"略画"、少写。
2. **写作顺序不必按"先怎样、再怎样"。** 如果你的 loss（创新点）在整个流程的最后面，仍然可以在 methodology 开篇先说明整体组织逻辑（呼应第四讲提到的"方法部分开篇要讲清楚整体逻辑"）——比如先说明"我的 loss 是通用的"，然后在已知输出形式（大家都通用）的情况下讲清楚这个 loss 怎么计算，最后再讲这个 loss 怎么和现有不同框架/方法结合——**而"怎么和现有方法结合"这部分明确不是你的创新，只是告诉别人这个东西怎么用**。所以不管在画图还是正文里，既有框架部分都不应该占最大篇幅，也不必按从头到尾的顺序先写。

**关于真实示例贯穿全程的重要性：** 于静老师强调，核心技术创新部分要通过详细过程、清晰的模块边界来展现，而且**一定要用一个和核心问题最直观相关的真实数据，贯穿整个方法描述的始终**：

> 如果你正文非常复杂的操作、一堆公式，这个公式最后输出来的效果是什么样，一定要非常直观地在图里体现，以及每一步效果之间的衔接——前一个过程输出这么一个东西，后面基于这个东西怎么样组合出一个什么样的东西，让读者能够自己"脑补"中间过程。**这其实就省去了你大量篇幅可能说不清的东西，这就是画图最大的作用。**

**训练与测试过程不同时要分开讲：** 如果图里训练过程和测试过程不一致，也要分开讲清楚。

**关于"用视觉手段表达道理而非只是重复过程"：** 于静老师特别称赞这张图的一个亮点——它通过非常形象的方式，展示了数据在空间分布上、经过每一步操作后是如何变化的（比如这一步操作后点的分布是什么样，下一步又变成什么样），从而直观地说明"为什么这样做背后能达到去偏置的效果"：

> 你画的图不是只是过程的重复展现，而是要用不同的手段去表达你背后的道理和效果。

## 四、四类代表性创新的框架图小结（PPT 第 11 页）

### 课堂讲解：四个案例的类型归纳

于静老师总结第七、八两讲一共举了四个具有代表性的创新类型案例：

1. **MuKEA**（第七讲）——针对老问题提出新思路（小模型）
2. **ET-BERT**（本讲）——提出全新框架（大预训练模型）
3. **DualVD**（本讲，赏析）——复杂过程如何画得清晰易懂的典范
4. **CogTree**（本讲，赏析）——创新点是通用组件（loss）时，既有框架该如何"略写"

### 幻灯片内容（PPT 第 11 页，原文精准转录）

标题：**论文模型框架图示意图——小结**

- 明确输入、输出、关键过程
- 突出创新，避免罗列非本文贡献内容
- 划分模块，明确各模块所解决问题
- 精准命名各个过程、变量、符号
- 一致——保证图示和正文相同语义内容［表达方式一致］

### 课堂讲解

> 我最后总结一下，不同的 contribution 画出来可能不太一样，那基本的原则是：

1. **必须明确输入、输出、关键过程**——这是图里一定要体现的最基本的东西。
2. **创新之处一定要用最大的篇幅去展现**（不管是图像的篇幅还是文字的篇幅），而不是按照做的过程中花最多时间的部分、或者方法从头到尾的实际顺序——一定要围绕创新、围绕你解决的问题去展开。
3. **要划分模块**，每个模块解决了中间的哪个环节、为什么能解决这个环节，要非常清楚地展示。
4. **所有画图里的模块、输入输出过程都要给出清晰准确的命名**——不要自己随便定义一个名字（那样又要花大篇幅去解释这个名字是什么意思），而应该用这个领域大家有共识的符号图形去表示，降低沟通成本。
5. **一定要一致：** 同一张图里，前后表达相同内容的符号必须用相同的表现形式；同时正文和图不管是命名还是符号，也必须与图保持一致。

## 附录：本讲核心概念速查

1. **新框架类工作的三大读者关切：** 表示问题（怎样把陌生数据转成模型能接受的输入）、任务设计问题（怎样设计预训练/训练任务）、迁移应用问题（怎样微调/应用到下游）——这是任何"提出全新框架"类工作都要在图里讲清楚的三件事。
2. **审稿人背景的不确定性：** 你不知道审稿人是否熟悉你的框架所属领域，因此既要让懂行的人认可你的创新，也要让完全外行的人接受你的框架能解决通用问题。
3. **不要被"看起来规范"迷惑：** 画面工整 ≠ 内容清晰；必须首先关注内容是否回答了核心创新问题，形式美观是次要的、后期才需要打磨的。
4. **画图前先写下来："这个图要回答哪几个创新问题？我的创新点是什么？通过哪个过程实现？"** 想清楚再画，而不是想到哪画到哪。
5. **色彩使用的陷阱：** 视觉最鲜艳、最吸引注意力的地方，恰恰应该是信息量最大（即最具创新性）的地方——避免把最花哨的颜色用在无关紧要的部分。
6. **示意图 ≠ 真实内容的完整复刻：** 只需要画出能达到"让读者理解你核心贡献"这一目的的那部分内容和恰当例子，不必展示全部原始信息。
7. **既有框架 vs. 本文创新的篇幅分配铁律：** 无论在图里还是正文里，既有框架/背景技术都应该"略画略写"，篇幅和详细程度都应该让位给真正的创新部分；创新点在流程后段时，写作顺序也不必被迫从头开始。
8. **真实示例贯穿全程的价值：** 用一个和核心问题最相关的真实数据/例子，贯穿方法描述始终，能让读者通过"看效果"自己脑补复杂的中间过程，节省大量解释篇幅——这是画图最大的作用。
9. **画图不是重复叙述，而是用视觉手段呈现"道理"：** 如展示数据分布随处理步骤变化的直观效果，比单纯罗列步骤更有说服力。
10. **框架图五大基本原则（通用小结）：** 明确输入/输出/关键过程 → 突出创新、避免罗列非本文贡献 → 划分模块并明确各自解决的问题 → 精准命名（善用领域共识符号）→ 全文表达一致（图与图内、图与正文）。
