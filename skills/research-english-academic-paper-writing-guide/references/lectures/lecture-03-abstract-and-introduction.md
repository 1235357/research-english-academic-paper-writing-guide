## 0. 本讲一页总览

本讲围绕英文论文中 **Abstract** 与 **Introduction** 两个部分展开。它不是单纯讲“摘要要短、引言要长”这种表层写法，而是在训练一种论文结构性思维：

**一篇好论文必须让问题、方法、实验互相呼应。**

更具体地说：

1. **摘要** 要在约 200 词内完成论文主逻辑的压缩表达：  
   **任务/挑战 → 现有方法问题 → 本文方法总思路 → 本文核心亮点 → 方法效果与领域意义**。

2. **引言** 要把摘要扩展开来，完成说服审稿人的主论证：  
   **研究背景与挑战 → 提出问题与原因 → 相关工作与不足 → 本文研究思路 → 本文主要贡献**。

3. 高水平论文与普通论文的区别不在于是否写了这些部分，而在于这些部分之间是否形成一个闭环：  
   - 高水平写法：问题有理有据且足够具体，方法针对问题设计，实验逐一证明方法并回应动机。  
   - 普通写法：问题是“大家都在研究所以我研究”，方法是“step1 → step2 → step3”，实验是“达到 SOTA 但缺乏分析”，最后问题、方法、实验各说各话。

4. 本讲使用两个论文案例建立写作范式：  
   - CVPR 2020: **Unbiased Scene Graph Generation from Biased Training**，用于讲摘要结构。  
   - IJCAI 2020: **Mucko: Multi-Layer Cross-Modal Knowledge Reasoning for Fact-based Visual Question Answering**，用于讲摘要与引言之间的对应关系，以及引言的展开方式。

## 1. 课程位置与本讲目标

上一讲讲的是论文标题。标题的功能是让读者快速知道论文“解决了什么问题、提出了什么方法或视角”。本讲进入标题之后的两个核心组成部分：**摘要**和**引言**。

讲者在开头明确指出：

- 摘要是标题内容的扩充。
- 摘要也是后续引言内容的概括。
- 摘要必须讲清研究动机、工作亮点、解决的问题与最终效果。
- 引言是摘要的扩展，而且是论文中最难的部分。
- 审稿人在接受方法和实验之前，首先要判断研究动机是否成立：**你做这件事有没有价值？你提出的问题是不是真问题？**

因此，本讲并不是在教固定模板，而是在训练一种判断：  
**一篇论文的 abstract 与 introduction 是否真的把“为什么做、做什么、怎么做、为什么有效、贡献在哪里”讲成了一个逻辑闭环。**

标题：一篇论文的组成——摘要

基本要求：

- 标题的扩充、引言的概括
- 涵盖动机、亮点、效果等
- 200词左右
- 逻辑清晰

**视觉版式描述**

页面采用蓝色页眉，正文区域留白较多。四条基本要求以蓝色手写风格字体展示，左侧配有黄色太阳形 bullet 图标。页面意图非常明确：先给摘要的定义和最低要求，再通过后续案例展开。

**课堂讲解复现**

讲者从上一讲“标题”自然过渡到“摘要”。摘要不是孤立的一段文字，它处在标题和引言之间：

- 相对于标题，摘要更具体，因此它是标题的扩充。
- 相对于引言，摘要更浓缩，因此它是引言的概括。

摘要需要覆盖三个核心问题：

1. **研究动机是什么？**  
   为什么这个任务、这个问题值得研究？它背后有什么挑战？

2. **工作亮点是什么？**  
   本文不是简单“做了一个模型”，而是要说清楚方法的关键思想或技术创新点。

3. **解决问题后的效果如何？**  
   不仅是“性能提升”或“SOTA”，还包括是否带来更普适、更可解释、更可信、更能启发领域后续工作的贡献。

讲者强调摘要篇幅大约 200 个词左右，关键是逻辑清晰。摘要必须让读者在极短时间内看到论文的完整逻辑链，而不是堆砌关键词。

### Slide 4：摘要案例拆解——Unbiased Scene Graph Generation from Biased Training

**页面文字内容**

页面主题仍是“一篇论文的组成——摘要”。

论文：**Unbiased Scene Graph Generation from Biased Training, CVPR 2020**

右侧彩色标注总结：

- **SGG存在的挑战：数据偏置**
- **SGG方法的问题：未区分偏置的好坏**
- **本文方法的思路：因果推断**
- **本文具体的亮点：构建因果图 → 反事实推断 → 优化目标**
- **本文方法的优势：**
  - 模型无关，广泛适用
  - 模型效果达到新 SOTA

**视觉版式描述**

左侧是论文摘要截图。摘要被不同颜色高亮：黄色、蓝色、红色、绿色、紫色等。每一段颜色通过箭头对应右侧总结。页面实际上把一个优秀摘要拆解成五个语义模块。

**课堂讲解复现**

讲者把这个摘要拆成五个部分，每个部分都承担不同的论证功能。

#### 4.1 第一部分：任务挑战

摘要第一句话先讲 **SGG 任务存在的挑战**。这篇论文把挑战定位为：SGG 仍然远未达到实用，主要原因是严重的训练数据偏置。例如，本来图像中有多样关系，如 “human walk on beach / sit on beach / lay on beach”，但模型可能全部塌缩成 “human on beach”。

这一步的写法要点是：  
**摘要开头必须先说清楚你所做任务或问题目前最大的挑战是什么。**

注意，这里的挑战不是空泛地说“任务很难”或者“性能不够好”，而是精确到“训练数据偏置导致关系预测塌缩，从而影响下游 VQA 等任务”。

#### 4.2 第二部分：现有方法问题

接下来摘要说明：传统去偏方法不能区分 **good bias** 与 **bad bias**。

讲者特别强调，摘要中不需要罗列所有现有方法，但必须点出现有方法的大体思路及其解决不了的关键问题。这里的问题不是随便挑一个，而是服务于后文方法的：

- 有些偏置是有帮助的，例如常见关系可以作为上下文先验。
- 有些偏置是有害的，例如长尾关系被高频词支配，导致细粒度关系无法被正确预测。
- 现有 debiasing 方法的问题是把偏置笼统处理，没有区分“好的偏置”和“坏的偏置”。

讲者指出：论文里的任何一句话都不是凭空写出来的。摘要中提出的“现有方法问题”必须是为了引出后面本文方法要解决的具体问题。

#### 4.3 第三部分：本文方法总思路

摘要中间有一句非常关键的话：本文提出一个基于 **causal inference** 而非传统 likelihood 的 SGG 框架。

讲者强调：  
这里还没有进入具体模块细节，不应该上来就说“我提出了几个模块，它们之间如何连接”。应该先用一句话概括整个方法的最高层思想，让审稿人快速知道你的框架是基于什么原则来解决问题。

这篇论文的写法是：

- 不是继续沿用概率统计式 likelihood。
- 而是从因果推断角度寻找真正的因果关联。
- 目标是区分主效应与偏置带来的副作用。

#### 4.4 第四部分：本文具体亮点

方法总思路之后，再进入核心亮点。讲者将这篇论文的亮点概括为：

**构建因果图 → 反事实推断 → 优化目标**

这里的重点不是把方法细节全部展开，而是把核心技术创新点按逻辑顺序组织起来。每一步都要让读者感到“这样做看起来能够解决刚才那个问题”。

具体来说：

1. 构建 SGG 的因果图。
2. 在训练图上进行反事实因果推断，推断 bad bias 的影响。
3. 使用 Total Direct Effect 作为最终 predicate score，使预测更无偏。

#### 4.5 第五部分：方法优势与效果

最后一部分写方法效果。讲者指出，效果不应该只是“我们超过所有模型”“我们达到 SOTA”。性能提升当然重要，但对领域来说更重要的是：

- 方法是否推动领域往前走。
- 是否对本质问题有新的发现或解决方式。
- 是否具有泛化能力。
- 是否模型无关、适用于更多模型。
- 是否提供可解释机制，帮助打破黑盒，实现可靠可信。

这篇论文在摘要最后强调：

- 框架对任何 SGG model 都是 agnostic 的，因此广泛适用。
- 在 Visual Genome benchmark 和多个模型上有显著提升，达到新的 SOTA。

#### 4.6 本页提炼出的摘要五段式

一个高质量摘要可以按如下语义顺序组织：

1. **任务/挑战**：这个任务为什么困难？核心挑战是什么？
2. **现有方法问题**：现有方法为什么不能解决这个挑战？
3. **本文方法总思路**：本文从什么新视角或总原则解决问题？
4. **本文核心亮点**：方法中最关键的创新步骤是什么？它们如何环环相扣？
5. **效果与意义**：方法如何有效？对领域有什么推进？

### Slide 5：一篇论文的组成——引言：基本要求

**页面文字内容**

标题：一篇论文的组成——引言

基本要求（摘要的扩展，最难的部分）：

- 研究背景与挑战
- 提出问题与原因
- 相关工作与不足
- 本文研究思路
- 本文主要贡献

**视觉版式描述**

页面布局与 Slide 2 相似，但强调“引言”而不是“摘要”。“最难的部分”用红色突出。五条要求以蓝色手写风格字体列出，左侧仍是黄色太阳形 bullet。

**课堂讲解复现**

讲者明确指出：**引言是一篇论文里最重要、也是最难写的部分。**

原因在于，审稿人判断方法和实验之前，会先判断：

- 你的研究动机是否成立。
- 你做这件事是否有价值。
- 你提出的问题是不是真问题。
- 如果问题本身不重要，方法再复杂也不重要。

引言要完成的任务不是简单写背景，而是要说服读者：  
**这篇论文解决的是一个真实、重要、具体的问题，并且本文方法正是针对这个问题设计的。**

引言基本包括五部分：

1. **研究背景与挑战**：领域为什么重要？当前最大的挑战是什么？
2. **提出问题与原因**：这个挑战背后的核心问题是什么？为什么它存在？
3. **相关工作与不足**：现有工作做了什么？它们为什么还不能解决这个问题？
4. **本文研究思路**：本文打算从什么角度、用什么原则解决？
5. **本文主要贡献**：本文不仅提出了一个方法，还对领域提供了什么可推广的思想、框架、视角、能力或证据？

### Slide 6：CCF-A 与 CCF-C 的引言/论文逻辑差异

**页面文字内容**

左侧：CCF-A

- 问题-方法-实验，相互呼应
- 问题：有理有据，足够具体
  - 背景阐述聚焦重点
  - 问题提出明确具体
  - 聚焦研究动机，总结现状问题
  - 基于研究动机，概述研究方法
  - 面向领域需求，拔高论文贡献
- 方法：针对问题设计，每一步设计目标明确
- 实验：针对方法逐一证明，针对动机逐一分析

右侧：CCF-C

- 问题-方法-实验，各为其说
- 问题：大家都在研究，所以我研究
- 方法：step1 → step2 → step3
- 实验：达到了 SOTA，缺乏分析

**视觉版式描述**

页面左右对比。左侧 CCF-A 用红色标题，强调问题、方法、实验之间的互相呼应。右侧 CCF-C 用绿色标题，突出普通论文常见的割裂式写法。页面是本讲最重要的判断框架之一。

**课堂讲解复现**

讲者用 CCF-A 与 CCF-C 的对比说明：高水平论文不是把摘要、引言、方法、实验分别写完整就可以，而是要形成逻辑闭环。

#### 6.1 高水平写法：问题-方法-实验相互呼应

高水平论文的引言必须做到：

- **问题有理有据**：不是一句“这个任务很重要”，而是用背景、例子、文献或任务需求说明为什么重要。
- **问题足够具体**：不是“多模态融合不好”这种泛化描述，而是能定位到当前任务真正卡住的核心机制。
- **背景聚焦重点**：背景不是百科介绍，而是服务于提出问题。
- **研究动机清晰**：问题不是为了铺垫一个流行方法，而是来自领域真实需求与现有方法局限。
- **方法概述基于动机**：方法不是模块堆叠，而是回答“为什么这样设计能解决刚才的问题”。
- **贡献面向领域需求**：贡献不是简单重复“我们提出了一个模型”，而是说明本文对领域可推广的推进。

方法部分要做到：每一步设计都有明确目标。  
实验部分要做到：针对方法逐一证明，针对动机逐一分析。

#### 6.2 普通写法：各说各话

普通论文往往呈现如下状态：

- 问题：大家都在研究，所以我也研究。
- 方法：step1 → step2 → step3，只描述流程，不解释为什么每一步必要。
- 实验：达到了 SOTA，但缺乏对原因、机制和问题回应的分析。
- 最终：问题、方法、实验各说各话。

这种写法的根本问题是没有建立从“需求/挑战”到“方法设计”再到“实验验证”的因果链。

### Slide 7：引言案例引入——IJCAI 2020 Mucko 论文

**页面文字内容**

标题：一篇论文的组成——引言

中心文字：IJCAI 2020

论文：**Mucko: Multi-Layer Cross-Modal Knowledge Reasoning for Fact-based Visual Question Answering**

作者：Zihao Zhu, Jing Yu, Yujing Wang, Yajing Sun, Yue Hu, Qi Wu

页面展示论文标题、作者与图示。图示中包括：

- 输入图像：街边红色消防栓。
- Dense captions：对图像中 woman、red fire hydrant、sidewalk、chain 等视觉内容的描述。
- Question：询问 red cylinder object in the image is used for what。
- Cross-modal knowledge reasoning 图：围绕 fire hydrant 组织 visual、semantic、fact 多层信息。
- Supporting fact：fire hydrant, UsedFor, firefighting。
- Answer：firefighting。

**视觉版式描述**

页面中央展示论文的 motivation 图。左侧是输入图像、dense captions 和问题，右侧是跨模态知识推理图。图中不同颜色标识视觉、语义和事实知识节点，体现多层跨模态知识推理。

**课堂讲解复现**

讲者说明这篇 IJCAI 2020 的论文之前在“研究动机”相关内容中已经讲过。本讲继续用它说明：摘要与引言如何对应，引言每个部分应该怎样写。

任务是视觉问答，具体是 **Fact-based Visual Question Answering, FVQA**。机器看到一张图像和一个问题，需要像人一样回答。关键难点在于：

- 不能只看图。
- 还要理解问题。
- 还要关联外部知识。
- 还要能把图像内容、语言语义和知识事实结合起来。

例如，问题问图中的 red cylinder object 是用来做什么的。模型必须识别它是 fire hydrant，并知道 fire hydrant 的外部知识用途是 firefighting，才能回答。

**课堂讲解复现**

#### 9.1 引言可以在主要实验结果后开始写

页面左下有醒目的手写标注：**有主要实验结果后可以动笔！**

讲者解释：Introduction 可以在主实验已经有靠谱结果后尽早动笔。因为此时你大概知道方法是否成立，实验能否支持动机。然后在继续补实验、改方法、看新论文的过程中，不断检查逻辑是否自洽、相关工作是否充分，直到投稿前打磨成熟。

#### 9.2 第一部分：大背景与核心挑战

Mucko 的大背景是 VQA。引言先说明 VQA 重要：它是让机器分析图像视觉内容和自然语言、并用自然语言回答问题的方向。

但对 FVQA 而言，仅仅看可见内容不够。它需要外部知识。讲者强调，背景段不能只说“多模态融合不好”这种泛泛挑战，而要提出自己的科研判断：

- 这个领域为什么重要？
- 当前任务最核心的问题是什么？
- 这个问题能否通过例子被准确说明？

本例中的核心挑战是：  
**如何捕获 question-oriented 且 information-complementary 的证据，使模型能够同时关联视觉、语义和事实知识。**

这里要特别区分两件事：

- **任务核心挑战**：当前任务本身真正困难在哪里。
- **相关工作不足**：现有方法在解决这个挑战时哪里做得不够。

很多同学会把这两者混在一起。引言第一部分要讲任务挑战；后面的相关工作部分才讲现有方法不足。

#### 9.3 第二部分：现有方法要分类归纳，而不是按时间罗列

讲者强调，介绍相关工作时，不能简单写：

A 做了什么，B 做了什么，C 做了什么，所以我要做什么。

这种写法只是流水账。正确做法是按技术脉络分类归纳。例如在 VQA/FVQA 中，可以按方法思想或技术路线归纳：

- 只依赖可见图像内容回答问题的方法。
- 引入外部知识但以关键词匹配或事实图检索为主的方法。
- 使用图结构或推理机制的方法。
- 缺乏细粒度选择、无法自适应捕获跨模态互补信息的方法。

每一类不需要罗列所有论文，而是概括其核心思想与局限，并引用代表性工作。Introduction 中的方法介绍与 Related Work 的区别在于：Introduction 只讲与本文立意最相关的技术脉络和不足；Related Work 才更系统地铺开。

#### 9.4 第三部分：评价现有方法必须准确、客观、专业

页面底部强调：**准确、专业评价**。

讲者提醒，在评价别人方法时：

1. 必须真正读过这些工作。
2. 评价必须准确、客观、专业。
3. 不能随意照搬别人如何评价某类方法。
4. 评价角度必须与你要解决的问题相关。
5. 不能把别人工作说得一无是处；应承认其推进作用，同时指出它在本文关注问题上的局限。

一个好的评价句不是“previous methods are ineffective”，而应说明：  
它们在某一前提下取得成功，但由于没有细粒度选择、没有跨模态互补证据建模、没有统一结构化表示等原因，无法解决本文要解决的挑战。

#### 9.5 第四部分：本文方法介绍必须呼应挑战与现有问题

讲者指出，方法介绍段必须回答两个问题：

1. 你的方法如何解决任务核心挑战？
2. 你的方法如何解决上一段指出的现有方法局限？

方法介绍的逻辑与摘要中的方法介绍一致：

- 先用一句话讲清整体思路：基于什么原理，解决什么问题。
- 再说明方法由哪些部分构成。
- 每一步说明其目的。
- 每一步说明它如何服务于整体挑战的某个环节。

在 Mucko 案例中，方法思路是：

1. 用统一的多模态异质图表示图像中的视觉、语义和事实信息。
2. 在统一结构化表示上进行跨模态知识推理。
3. 使用 modality-aware heterogeneous graph convolutional network 捕获与问题最相关的证据。
4. 通过 intra-modal graph convolution 选择每个模态内部证据。
5. 通过 cross-modal graph convolution 聚合不同模态间互补信息。
6. 多次迭代推理后预测答案。

这里的关键不是“用了 GNN”本身，而是“统一结构化表示 + 自适应选择 + 跨模态互补证据聚合”如何解决 FVQA 的核心挑战。

#### 9.6 第五部分：贡献要凝练方法的普适性，而不是重复方法步骤

贡献部分最容易与方法介绍重复。讲者强调：

> 贡献不是你具体的方法步骤，而是你的思想、框架或技术手段对领域的启发。

贡献可以从这些角度凝练：

- 提出了新问题吗？
- 解决问题提供了新视角吗？
- 实现了新框架吗？
- 提出了新方法吗？
- 达到了新的 SOTA 吗？
- 模型具备了新能力吗？
- 实验证明了这种能力吗？
- 方法是否可解释，能否揭示推理过程？

其中，SOTA 不是最重要的贡献。真正重要的是：  
**性能提升是否来自方法确实解决了你提出的挑战，而不是偶然的工程堆叠。**

## 3. 本讲核心方法论：Abstract 的写作逻辑

### 3.1 Abstract 的定位

Abstract 是一个压缩系统，不是一个宣传语。它必须同时承接标题、压缩引言：

- 标题回答：这篇论文大概是什么？
- 摘要回答：这篇论文为什么做、做了什么、怎么做、做得怎样？
- 引言回答：为什么这个问题重要，为什么现有方法不够，为什么本文方法成立，贡献在哪里？

因此，摘要写得好不好，取决于你是否已经理解了整篇论文的立意和论证链。

### 3.2 Abstract 的五槽结构

| 槽位 | 要回答的问题 | 写作功能 | 常见错误 |
|---|---|---|---|
| 1. 任务与挑战 | 当前任务为什么重要、难在哪里？ | 建立研究动机 | 只说任务热门，不说具体挑战 |
| 2. 现有方法问题 | 现有方法为什么解决不了？ | 引出本文问题 | 罗列一堆工作，不归纳共性不足 |
| 3. 本文方法总思路 | 本文从什么核心视角解决？ | 快速建立方法原则 | 上来讲模块细节 |
| 4. 具体技术亮点 | 方法中哪些关键步骤环环相扣？ | 展示创新点 | step1/step2/step3 但不说明目的 |
| 5. 效果与领域意义 | 方法带来什么性能、泛化、解释或能力？ | 证明有效并升华贡献 | 只写 SOTA，缺少机制和意义 |

### 3.3 Abstract 的推荐写作顺序

虽然摘要在论文中位于最前，但实际写作中可以较晚完成：

1. 题目基本确定。
2. Introduction 主线基本清楚。
3. 方法部分初步写完。
4. 主实验有可信结果。
5. 从 Introduction 中抽取每段主旨，压缩成摘要。
6. 一直打磨到投稿前。

### 3.4 Abstract 的句子级模板

下面给出可操作模板。它不是要机械套用，而是帮助检查逻辑槽位是否完整。

```text
[Task/Background] X has become important for Y because ...
[Challenge] However, X remains challenging due to ...
[Existing limitation] Existing methods mainly ..., but they fail to ...
[Core idea] To address this problem, we propose ..., which ...
[Technical highlights] Specifically, we first ..., then ..., and finally ...
[Effects/Contribution] Experiments on ... demonstrate ..., and further analysis shows ...
```

中文逻辑对应：

```text
[背景/任务] X 对 Y 很重要，因为……
[挑战] 然而，X 仍然受到……的限制。
[现有方法问题] 现有方法通常……，但它们无法……
[本文总思路] 为解决该问题，本文提出……，从……视角……
[具体亮点] 具体而言，本文首先……，然后……，最后……
[效果/意义] 在……上的实验表明……；进一步分析说明……
```

### 3.5 Abstract 审稿人视角检查

写完摘要后，用以下问题自查：

- 第一眼能看出任务和挑战吗？
- 现有方法问题是否具体，而不是泛泛说“insufficient”？
- 本文方法是否先有总思路，再有具体步骤？
- 方法步骤之间是否有因果关系？
- 每一步是否对应前面提出的问题？
- 结果是否只写 SOTA，还是说明了模型能力、普适性、可解释性或领域意义？
- 摘要是否可以被压缩成一个完整逻辑链，而不是五句互不相关的话？

## 4. 本讲核心方法论：Introduction 的写作逻辑

### 4.1 Introduction 的定位

Introduction 是论文中最重要、最难写的部分。它必须完成三个层面的说服：

1. **问题真实**：不是伪需求，也不是为了套方法临时编出的需求。
2. **问题重要**：解决它能推进领域、任务或应用。
3. **方法对症**：本文方法的设计是从问题出发，而不是拿着锤子找钉子。

如果引言没有证明“问题重要”，那么方法与实验再多也难以说服审稿人。

### 4.2 Introduction 的五段式论证

| 段落功能 | 核心任务 | 写作重点 |
|---|---|---|
| 1. 背景与挑战 | 说明领域重要性和任务核心挑战 | 用文献、例子、应用或任务需求聚焦问题 |
| 2. 提出问题与原因 | 从挑战中凝练可研究的小问题 | 区分任务挑战与现有方法不足 |
| 3. 相关工作与不足 | 分类归纳现有技术路线 | 按技术脉络分类，不按时间流水账 |
| 4. 本文研究思路 | 说明本文如何解决问题 | 先讲总思路，再讲模块；每步说明目的 |
| 5. 本文主要贡献 | 提炼方法的普适性与领域意义 | 贡献不是重复方法，而是思想/视角/框架/能力 |

### 4.3 Introduction 的段落展开模板

#### 第一段：背景与挑战

```text
X is an important task for Y because ...
Despite recent progress, X remains challenging when ...
The key challenge lies in ...
```

写作原则：

- 背景不是百科全书。
- 背景必须服务于挑战。
- 挑战必须具体到当前任务的核心困难。
- 不能只说“融合不好”“表示不充分”“鲁棒性差”这种泛化表达。

#### 第二段：现有方法分类与不足

```text
Existing methods can be roughly grouped into ...
The first line of work ...; the second line of work ...
Although these methods ..., they still ...
```

写作原则：

- 必须分类归纳，而不是逐篇罗列。
- 每一类说明核心思想和局限。
- 只引用代表性工作。
- 局限必须与本文要解决的问题相关。

#### 第三段：本文方法思路

```text
To address this challenge, we propose ...
The main idea is to ...
Specifically, we first ... to ...
Then, we ... so that ...
Finally, we ...
```

写作原则：

- 先讲方法总思想。
- 再讲关键模块。
- 每个模块都要说明目的。
- 每一步都要回应前文挑战或现有方法不足。

#### 第四段：贡献凝练

```text
Our main contributions are summarized as follows:
(1) We identify/formulate ...
(2) We propose ...
(3) We demonstrate ...
```

写作原则：

- 贡献不是“我们提出了一个模型”这么简单。
- 贡献要有抽象层次：新问题、新视角、新框架、新方法、新能力、新证据。
- SOTA 只能是贡献之一，不是贡献全部。
- 实验贡献要说明方法为什么有效，而不是只报告数字。

### 4.4 Introduction 中最常见的错误

1. **背景过大、问题过空**  
   大量介绍领域历史，却没有引出本文要解决的具体问题。

2. **把任务挑战和方法不足混淆**  
   任务挑战是任务本身的核心难点；方法不足是现有技术路线在应对该挑战时的局限。

3. **相关工作按时间流水账**  
   A 做了什么，B 做了什么，C 做了什么，最后没有技术脉络。

4. **评价他人不准确、不专业**  
   没有真正读懂论文，就用笼统负面评价引出自己的方法。

5. **方法介绍变成模块列表**  
   step1 → step2 → step3，但每一步为什么必要没有说明。

6. **贡献重复方法**  
   前面已经讲了方法，贡献部分又重复“我们提出了某某模块”。

7. **SOTA 崇拜**  
   实验只强调达到 SOTA，缺乏对动机和机制的分析。

## 5. “问题-方法-实验”闭环

本讲最关键的判断标准是：

```text
问题：有理有据，足够具体
方法：针对问题设计，每一步目标明确
实验：针对方法逐一证明，针对动机逐一分析
```

### 5.1 问题如何写得具体？

错误表达：

```text
Multimodal fusion remains challenging.
```

更好的表达应继续追问：

- 哪些模态？
- 融合为什么困难？
- 是缺少统一表示？
- 是信息选择不细？
- 是互补证据无法聚合？
- 是噪声被引入推理？
- 是模型无法解释选择过程？

最终要写成可解决的小问题，而不是停留在宏观挑战。

### 5.2 方法如何针对问题？

方法设计必须能回答：

- 这个模块解决哪个问题？
- 这个设计与前文挑战有什么对应关系？
- 为什么不用现有方法？
- 为什么这个思路比已有技术路线更适合？
- 每一步的中间目标是什么？
- 如果删掉这一步，哪些挑战无法解决？

### 5.3 实验如何回应动机？

实验不能只有主表格。必须形成证明链：

- 主实验：方法整体有效。
- 消融实验：每个模块确实有贡献。
- 对比实验：本文思路比现有技术路线更适合。
- 分析实验：性能提升来自解决了本文提出的问题。
- 可视化/案例：模型具备本文声称的新能力。
- 泛化实验：方法在不同数据集、任务或模型上仍有效。
- 失败案例：诚实说明局限，反过来体现严谨性。

## 6. 两篇案例论文的结构化复盘

### 6.1 CVPR 2020: Unbiased Scene Graph Generation from Biased Training

这篇论文用于展示摘要写法。

**任务：** Scene Graph Generation。  
**挑战：** 训练数据存在严重偏置，导致关系预测塌缩，图结构难以支持 VQA 等下游任务。  
**现有方法问题：** 传统 debiasing 不能区分 good bias 与 bad bias。  
**方法总思路：** 从因果推断而非传统 likelihood 角度解决偏置。  
**具体亮点：** 构建因果图，进行反事实推断，使用 Total Direct Effect 作为无偏 predicate score。  
**优势：** 模型无关、广泛适用，在 Visual Genome 与多种模型上显著提升。

这个摘要的价值在于：每一句都服务于下一句。挑战引出现有方法问题，现有方法问题引出因果推断，因果推断引出 TDE，TDE 引出模型无关与 SOTA。

### 6.2 IJCAI 2020: Mucko

这篇论文用于展示摘要与引言的对应关系。

**任务：** Fact-based Visual Question Answering。  
**背景：** VQA 要求机器理解图像和自然语言。  
**挑战：** FVQA 需要外部知识，关键是捕获 question-oriented 和 information-complementary 的证据。  
**现有问题：** 现有 FVQA 方法往往把所有信息联合嵌入，缺乏细粒度选择，容易引入噪声。  
**方法总思路：** 用多模态异质图表示视觉、语义和事实信息，并通过跨模态知识推理捕获互补证据。  
**关键方法：** modality-aware heterogeneous graph convolutional network；intra-modal graph convolution；cross-modal graph convolution；iterative reasoning。  
**贡献：** 构建统一的多层信息图表示，提出跨模态知识推理框架，提升 FVQA 性能并提供可解释性分析。

它对引言写作的启发是：  
引言不是把摘要变长，而是把摘要里的每个判断变成可被审稿人接受的论证。

## 7. 可直接用于写作的工作流

### 7.1 写 Abstract 前的准备

先回答下列问题：

```text
我的任务是什么？
这个任务为什么重要？
任务当前最核心的挑战是什么？
现有方法处理这个挑战时的共性问题是什么？
我的方法最高层思路是什么？
我的方法中真正新颖且必要的步骤是什么？
每一步如何解决前面的问题？
实验结果证明了什么？
除 SOTA 外，我的方法给领域提供了什么启发？
```

如果这些问题回答不出来，不要急着写摘要。

### 7.2 写 Introduction 前的准备

先画出这条链：

```text
领域需求
  ↓
任务挑战
  ↓
可解决的小问题
  ↓
现有技术路线分类
  ↓
每类方法的关键不足
  ↓
本文方法总思路
  ↓
方法模块与挑战逐项对应
  ↓
实验如何证明
  ↓
贡献如何升华
```

这条链如果断裂，引言就会出现“各说各话”。

### 7.3 修改 Introduction 的顺序

1. 先检查第一段是否把背景聚焦到核心挑战。
2. 再检查现有方法是否按技术路线归纳。
3. 再检查对现有方法的评价是否准确客观。
4. 再检查方法段是否先讲总思路，再讲步骤。
5. 再检查每一步方法是否有目的。
6. 再检查贡献是否具有抽象层次。
7. 最后反向检查：贡献是否能被实验支撑，实验是否能回应动机，方法是否真的针对问题。

## 9. 课堂知识转化成 Skill 的核心原则

将本讲转化成 Agent Skill 时，不应把 transcript 简单塞进 prompt，而应把其中可复用的“行动规则”提炼出来：

1. **任何英文论文写作任务都先检查问题-方法-实验闭环。**
2. **写摘要时强制使用五槽结构：挑战、现有问题、总思路、亮点、效果。**
3. **写引言时强制使用五段论证：背景挑战、问题原因、相关工作不足、研究思路、主要贡献。**
4. **现有方法必须分类归纳，不能流水账。**
5. **方法介绍必须说明每一步的目的和与问题的对应关系。**
6. **贡献必须从具体方法升华到领域启发，不能重复模块列表。**
7. **SOTA 不是最重要贡献；实验必须证明方法确实解决了提出的问题。**
8. **在主要实验结果可信之后尽早写 Introduction，并持续修改到投稿前。**

### 幻灯片内容（原文精准转录）

**PPT 第 4 页** 展示该论文摘要原文全文，并以彩色标注拆解出五个部分（原文照录，标注含义据课堂讲解还原）：

> *"Today's scene graph generation (SGG) task is still far from practical, mainly due to the severe training bias, e.g. collapsing diverse "human walk on / sit on / lay on beach" into "human on beach". Given such SGG, the down-stream tasks such as VQA can hardly infer better scene structures than merely a bag of objects."*
> —— 标注：**SGG 存在的挑战：数据偏置**

> *"However, debiasing in SGG is not trivial because traditional debiasing methods cannot distinguish between good and bad bias, e.g., good context prior (e.g., "person read book" rather than "eat") and bad long-tailed bias (e.g., "near" dominating "behind / in front of")."*
> —— 标注：**现有方法的问题：无法区分好坏偏置**

> *"In this paper, we..."*（本文提出的大思路一句话）
> —— 标注：**本文方法的性质：因果推断**

> *"We first build a causal graph for SGG, and perform traditional biased training with the graph. Then, we propose to draw the counterfactual causality from the trained graph to infer the effect from the bad bias, which should be removed. In particular, we use Total Direct Effect as the proposed final predicate score for unbiased SGG."*
> —— 标注：**本文方法的具体步骤：构建因果图 → 反事实推断 → Total Direct Effect 预测得分**

> *"By using the proposed Scene Graph Diagnosis toolkit on the SGG benchmark Visual Genome and several prevailing models, we observed significant improvements over the previous state-of-the-art methods."*
> —— 标注：**本文方法的效果：显著优于现有 SOTA 模型**

### 课堂讲解

于静老师用不同颜色标出摘要中对应上述五部分的具体语句，逐一带读：

**第一部分（挑战）：** 第一句话在介绍现在场景图生成任务存在的挑战——数据偏置，导致很多关系难以准确判断。她强调，写摘要一定要先写清楚"你所做的任务或解决的问题，目前存在的最大挑战是什么"。

**第二部分（现有方法的问题）：** 第二部分要介绍：既然任务存在数据偏置这一挑战，现有方法在解决这个挑战时用的思路是什么，以及这些思路存在的问题——不需要在摘要里罗列所有方法，但需要点出大概思路和其局限。本例中现有方法最大的问题是"不能区分数据里好的偏置和不好的偏置"（有些偏置其实是数据量大带来的良好先验，能帮助判别；有些偏置反而干扰判断）。她特别强调：**"论文里的任何一句话都不是凭空随意写出来的"**——点出这个具体问题，是因为后面提出的方法正是为了解决这个挑战里对应的这个问题。

**第三部分（一句话大思路，承上启下）：** 这句话非常关键——针对上述问题，本文提出一个什么样的方法思路，这里**还不是**写具体第一步第二步第三步怎么做，而是先用一句话概括出解决问题的大思路（本例中是"基于因果推理而非传统概率统计思路，寻找真正的因果关联"）。于静老师建议初写论文的同学不要一上来就写模块细节，而要**先把整体思路用一句话最简洁地概括出来**，这样能让审稿人迅速抓住整个框架或技术路线的立足点。

**第四部分（具体亮点/步骤，环环相扣）：** 下一句话开始具体化方法里的亮点——不是非常细节的完整过程，而是核心的几个技术创新点，且这几个创新点之间必须体现清晰的逻辑关系（环环相扣的叙述），让审稿人能直接感受到"这样做看起来是能够解决刚才那个问题的"——每句话都应该点出它和解决问题之间的关系。本例的思路是：构建因果图 → 通过反事实推理找到真正的因果关联 → 通过优化目标学到具有无偏预测的场景图生成目标。

**第五部分（效果）：** 效果不是简单罗列"达到了最好效果、超过了所有模型"（这只是证明方法有效性的前提），于静老师认为对领域更重要的是：**方法对领域的推进、对本质问题的发现和解决是否有新的启发**——例如模型是否具有泛化能力（在不同任务上解决类似问题）、模型是否提供了可解释的方式（打破黑盒，让人看到内部运作机理，从而提升可靠性/可信度）。这些启发性内容可以放在摘要最后来介绍。

> 所以我想说，不管是什么类型的论文、什么样的主题，如果你按照这五个方面依次去看你的 abstract 是不是能够覆盖，以及它们之间的逻辑关系是不是能够像这样环环相扣，并且每一部分你能够把核心亮点以及它和上一部分之间的逻辑关系讲清楚，我觉得这就是一个非常好的 abstract。

**关于摘要的写作时机（重要提醒）：** 于静老师特别指出，摘要在整篇论文里可以是**最后面才写**的部分——即在 introduction 和 method 部分大概写完之后，再写 abstract；但摘要仍会随着 introduction 思路的不断完善而反复修改打磨，一直改到投稿之前，因为摘要本质上是 introduction 的进一步简略概括。

## 三、一篇论文的组成——引言：五段式结构总览（PPT 第 5 页）

### 幻灯片内容（原文精准转录）

标题：**一篇论文的组成——引言**

基本要求（摘要的扩充，最难的部分）：
- 研究背景与挑战
- 核心问题与原因
- 相关工作与不足
- 本文研究思路
- 本文主要贡献

### 课堂讲解

> 引言，其实我觉得是一篇论文里面最重要也是最难写的部分。

于静老师解释了 Introduction 为何如此关键：审稿人在看方法或实验之前，更关键的前提是判断"你的思路、你做这项研究的动机是不是成立"——即这件事是否有价值、这个问题是否是真问题。**如果这个前提不成立（或比较弱），那么具体用什么方法就不重要了，因为你研究的这个问题本身就不重要。** 只有你的方法解决了一个重要问题，这个方法才是重要的方法。因此，Introduction 里如何把问题讲清楚、讲出其重要性，直接决定了别人是否真正接受你方法的价值。

Introduction 需要涵盖的五个主要部分（与摘要的五部分一一对应但展开更详细）：研究领域背景和存在的挑战 → 针对这个挑战核心的问题是什么 → 现有相关研究工作针对这个问题的方法有哪些不足 → 本文针对现有方案不足的解决思路是什么 → 本文在方法技术上到底有什么样的贡献。

- 问题提出明确具体
- 基于研究动机，凝结现状问题
- 基于研究动机，搭建研究方法
- 面向领域需求，提高论文贡献
- 方法：针对问题设计，每一步设计目标明确
- 实验：针对方法逐一证明，针对动机逐一分析

**CCF-C（对比）：**
- 问题—方法—实验，各自其说
- 问题：大家都在研究，所以我研究
- 方法：step1 -> step2 -> step3
- 实验：只看结果，缺乏分析

### 课堂讲解

于静老师说明这里先不详细展开概念，而是直接拿一篇具体论文来示范讲解——为了和前面题目、摘要讲解的示例形成呼应，便于理解，沿用第二讲已经介绍过的 2020 年 IJCAI 论文（即 Mucko）继续讲解。

## 五、引言范文精讲：以 Mucko（IJCAI 2020）为例逐段拆解（PPT 第 7–9 页）

### 幻灯片内容（原文精准转录）

**PPT 第 7 页** 重现 Mucko 论文首页信息（作者、单位同第二讲）与动机图（Input → Cross-Modal Knowledge Reasoning，含"红色消防栓用于灭火"示例问答）。

**PPT 第 8–9 页** 展示该论文 Abstract 与 Introduction 全文（学术论文原始排版截图），并以彩色文字在旁批注对应的写作逻辑环节。批注原文（据 OCR 识别 + 课堂讲解交叉核对）包括：

- **大背景**
- **挑战：引入互补知识**
- **现有方法问题：无法自适应地……（从不同模态信息里关联互补信息）**
- **从具体方法归纳问题 → 可解决的小问题**
- **方法介绍：呼应挑战和问题，如何解决问题**
- **贡献：凝练方法的普适性**，并列出一组自问自答式的贡献判断清单：
  - 提出的新问题？
  - 解决的新视角？
  - 实现的新框架？
  - 实现的新方法？
  - 达到的新 SOTA？
  - 具备的新能力？

### 课堂讲解

于静老师用不同颜色分别标出摘要和 introduction 里表达相同意思的内容，逐部分对照讲解：

**第一部分（大背景 + 核心问题）：** 她指出这一部分应该体现两件事：第一，这个领域现在重不重要——即为什么研究视觉问答这个任务是重要的事情（可以理解为让机器像人一样理解多模态信息表征和关联，这是一种智能水平的体现），需要通过参考文献、举例、说明重要性、应用场景等方式把重要性讲出来。第二，既然这么重要，现在这个任务里核心的问题到底是什么——本例中概括为"怎么样能够像人一样同时关联视觉、语言的语义以及知识，形成互补的知识表示和推理能力，才能回答这样的问题"。她特别提醒：**很多同学容易混淆"任务的核心挑战"与"后面相关工作存在的具体问题"**，这是本部分和下一部分（相关工作）的关键边界。这里泛泛地说"问题是多模态知识融合得不好"是不够的——这种描述太 general，没有针对性地回答核心问题到底是什么。

**第二部分（相关工作与不足）：** 于静老师强调这一步必须包含两部分：第一，现有方法要"分类归纳"介绍，而不是笼统按时间顺序"A 做了什么、B 做了什么、C 做了什么，所以我要做什么"——而是要把这些方法按技术脉络归纳成几大类（例如：最早基于特征融合 → 后面加入图神经网络 → 图神经网络方法目前又存在什么问题），指出最新一类方法的局限性；且只需引用代表性工作，不需要罗列所有相关工作（这一点与 Related Work 章节的写法有很大区别，后者会更详尽）。第二，在评价他人工作时，**必须准确、客观、专业**：一定是要看过这些工作才能评价，不能人云亮云；评价要客观，不能说别人的工作都是有问题的（肯定存在推进作用），也要清楚地指出哪里做得好、哪里做得不够。

**第三部分（本文方法介绍，呼应挑战与问题）：** 方法介绍必须呼应前面提出的挑战和问题：第一，方法怎么样解决整个领域核心任务的挑战；第二，方法怎么样解决现有方法存在的局限性。写法逻辑与摘要部分一致——先用一句话讲清楚方法的大思路（基于什么原理、解决什么问题），再讲方法分成哪几部分/模块、先怎么做、再怎么做、最后怎么做，且每一步要表达清楚"这样做的目的是达到一个什么中间过程，而这个中间过程是为了解决整体挑战的哪一个环节"。以 Mucko 为例：第一步提出多模态信息表示的统一框架（用图的形式统一表示视觉、语言、知识三种信息，以支撑后续自适应关联）；第二步基于该统一表征框架，提出异质图神经网络自适应获取不同模态信息互补的特征表示方法，最终形成对同一概念多模态互补理解，支撑最终答案判断。

**第四部分（贡献）：** 于静老师指出这是同学们最容易和"方法介绍"部分重叠的地方——很多人写贡献时仍然是"我提了这么一个方法，这个方法怎么怎么实现"，这其实还是方法本身，不是贡献。**贡献不是具体方法，而是你的思想、框架、提出的新技术手段对领域其他工作的启发。** 她给出一组判断贡献类型的清单（对应上方 PPT 批注）：

1. **提出的新问题？**——她坦言这个很难，一般到科研中后期才可能做到，比如提出一个新数据集来推动一个新问题；
2. **解决的新视角？**——比如以前从没有人从认知角度考虑这个问题，你在认知理论上发现一个新机理并应用到机器理解过程中；
3. **实现的新框架？**——比如以前大家都用扁平特征，你用 graph 的形式表示信息；
4. **实现的新方法？**——比如以前大家都用 CNN，你现在用了 GNN，或用了 transformer 等新方法；
5. **达到的新 SOTA？**——于静老师明确指出这**不是**最重要的一条，真正重要的是效果提升是否真的是因为方法解决了所说的挑战问题而带来的（这需要靠实验证明，将在后续讲次详细介绍）；
6. **具备的新能力？**——即模型是否具备了一种新的能力。

> 所以整个大家可以看到，其实你把 introduction 写好之后，你的 abstract 自然就可以通过每段的一个概括，再稍加修饰对应语言的连贯性，就可以形成你的 abstract。

**关于引言的写作时机（重要提醒）：** 于静老师建议 introduction 可以等到主实验结束、模型已经有一个靠谱结果之后就开始动手写，**越早写越好**；然后在后续边改实验、边完善方法和实验写作的过程中，会不断反思整体逻辑是否呼应，也会在看到新发表的工作时发现 related work 是否写得不够充分——这个过程会一直持续修改到投稿之前，才能得到一个自圆其说、逻辑自洽的好引言。

## 附录：本讲核心概念速查

1. **摘要 = 标题的扩充 + 引言的概括**，约 200 词，五段式：挑战 → 现有方法的不足 → 本文思路（一句话）→ 具体亮点（环环相扣）→ 效果（不止 SOTA，更看重启发/泛化/可解释性）。
2. **"论文里任何一句话都不是凭空写的"** ——摘要/引言中每一句都要服务于后文即将提出的方法，点出的问题要与自己方法所解决的问题精确对应。
3. **引言是全文最重要也最难写的部分**：审稿人先判断问题是否成立/重要，再看方法是否重要——问题不成立，方法就不重要。
4. **引言五段式：** 研究背景与挑战 → 核心问题与原因 → 相关工作与不足 → 本文研究思路 → 本文主要贡献。
5. **易混淆的边界：** "任务的核心挑战"（背景部分）≠"相关工作存在的具体不足"（相关工作部分）；"方法介绍"≠"贡献"（贡献是方法之上的思想/框架/启发，非方法本身复述）。
6. **评价他人工作三原则：** 必须读过原文；评价要准确客观专业；不能一概而论（每个工作都有推进作用，也有局限）。
7. **贡献六问：** 提出新问题？解决新视角？实现新框架？实现新方法？达到新 SOTA（非最重要）？具备新能力？
8. **写作时机建议：** Introduction 越早动笔越好（有初步靠谱结果即可开始），持续修改到投稿前；Abstract 反而适合放到 Introduction 和 Method 基本成型后再写，也会持续打磨到投稿。
